# LogiLink 입고 업무프로세스 정의서 v1.5

> 핵심 원칙
> 1. **모든 단계는 시작 트리거와 종료 시점·종료 상태가 명확해야 한다.**
> 2. **확정된 전표는 고치지 않고 앞으로만 진행한다.** 변경분은 차이 기록이나 새 전표로 처리한다.
> 3. **물리(어느 차량에 실렸는가)와 논리(어느 입고예정을 채우는가)를 분리해 기록한다.** 상차·검수는 실린 그대로 기록하고, 입고예정 귀속은 검수 확정 시 규칙으로 자동 배분한다.
> 4. **모든 화주사는 ASN 등록과 상차등록을 반드시 거친다.** 당일 ASN에 없는 품목은 실을 수 없다.

## 3. 단계별 상세

### ① 입고예정 등록 (화주사, Web)

화주사는 입고할 품목과 수량을 등록한다. 등록 방식은 직접 입력(품목 찾기), 엑셀 업로드, 카카오톡·이메일 이미지의 AI 판독 세 가지이다. AI 판독 결과는 저장 전까지 전표가 아닌 **초안(임시 데이터)**이다.

AI 판독이나 엑셀에서 품목 마스터와 매칭되지 않은 라인, 또는 신뢰도가 낮은 수량은 "확인 필요"로 강조한다. 원본 이미지와 유사 품목 후보를 함께 보여 주어 사용자가 직접 매칭하게 하고, 실제 신규 품목일 때만 품목 등록 요청으로 보낸다. **저장 시점에 미매칭 라인은 0건**이어야 한다. AI 원본 결과와 사용자 수정 내용은 모두 AI 판독 작업 테이블에 보존한다.

저장하면 입고예정 전표가 생성되고 상태는 **승인대기**가 된다. 3PL이 승인하거나 반려하기 전까지 화주사는 자유롭게 수정·취소할 수 있다. 저장할 때마다 **version**이 1씩 올라간다. 삭제는 물리 삭제가 아닌 "취소" 상태로 남긴다.

### ② 입고 승인 (3PL 운영담당, Web)

별도의 검토시작 단계는 두지 않는다. 입고예정 수정은 빈번하지 않으므로, 3PL이 화면을 연 시점의 version을 기억해 두고 **승인·반려 버튼을 누를 때 현재 version과 비교**한다. 다르면 "화주사가 수정한 건입니다. 변경 내용을 확인 후 다시 처리하세요"라는 안내와 함께 처리를 막는다(낙관적 잠금). 여러 건을 일괄 처리할 때는 건별로 판정해 바뀐 건만 실패시킨다.

승인은 **전표 단위**로만 하며 라인별 부분 승인은 하지 않는다. 승인하면 **승인 차수(approved_revision_no)**를 헤더에 기록하고 수정을 잠근다.

반려 시 사유는 필수이다. 반려하는 순간 헤더와 라인 전체를 **반려본 스냅샷**(n차, 사유, 처리자, 일시)으로 별도 보관한다. 스냅샷은 수정·삭제할 수 없다(Append-only). 화주사는 반려 사유와 반려본을 확인해 수정하거나 그대로 재저장하며, 이때 **차수(revision_no)**가 1 올라가고 승인대기로 돌아간다. 3PL 화면에서는 직전 반려본 대비 변경 내역을 비교할 수 있다. version은 저장마다 올라가는 동시성 제어용 값이고, 차수는 반려 후 재요청할 때만 올라가는 업무 회차이다. 둘은 구분해서 관리한다.

승인된 전표는 되돌리지 않는다. 수량이 줄면 검수 시 부족으로 기록되어 잔량으로 남고, 수량 증가나 품목 변경은 추가분을 새 입고예정으로 등록한다. 화주사가 입고 자체를 취소한 경우에는 3PL이 **승인 건 취소**를 한다. 후행 전표(ASN·검수)가 없을 때만 가능하고 사유가 필수이며, 결과는 최종 상태 "취소"이다.

### ③ ASN 등록 (화주사, Web, 필수)

화주사는 차량을 선택해 **승인되고 아직 종결되지 않은 입고예정**을 차량별로 분배한다. 입고예정일과 출고일이 달라도 된다. 따라서 전날 잔량도 다음 날 ASN으로 보낼 수 있다. ASN 헤더는 차량 단위이고, 입고예정 연결은 **ASN 라인 단위**이다. 그래서 한 차량에 여러 입고예정이 실릴 수 있다. 이 시점의 ASN 수량은 **지시수량(계획)**이며, 저장과 동시에 차량별 **상차지시서(바코드 포함)**가 발행된다.

모든 입고는 ASN에 포함된 품목·수량만 대상이다. 승인됐지만 ASN에 넣지 않은 품목을 실어야 한다면, 화주사가 상차 전에 Web에서 ASN을 **추가 등록**한다. 이것은 화주사가 정식으로 만드는 지시이다.

### ④ 차량별 상차등록 (화주사 상차담당, PDA, 필수)

상차 실적은 ASN과 독립된 **차량 단위 문서**이며, 상차지시서를 선택적으로 참조한다.

- **지시 상차:** 상차지시서 바코드를 스캔해 시작한다.
- **무지시 상차:** 예정에 없던 차량이 생기면 PDA에서 "무지시 상차"를 선택하고 차량번호를 입력해 시작한다. 지시 없이 실적만 생성하며, ASN을 만들지 않는다.

**작업자 잠금은 두지 않는다.** 한 차량을 여러 작업자가 동시에 작업할 수 있다. 품목 바코드를 스캔한 뒤 수량을 입력하며, 입력값의 의미는 **"추가로 실은 수량"**이다. 입력 한 건은 작업자·단말·시각과 함께 한 행으로 쌓이고, 품목별 상차수량은 그 합계로 계산한다. 상차완료 전까지는 본인 입력 건만 정정·삭제할 수 있다. 각 PDA에는 품목별 실시간 합계와 지시수량을 함께 보여 준다.

품목은 **같은 화주사의 당일 ASN에 등록된 품목**만 입력할 수 있다. 이 차량의 ASN만이 아니라 당일 전체 ASN이 기준이며, 그 외 품목은 차단한다. 당일 ASN 합계보다 많이 싣는 경우는 경고와 사유 입력만 받는다. 즉 **품목은 엄격하게, 수량은 유연하게** 본다.

완료할 때 현재 작업 중인 인원과 품목별 합계를 보여 주고 확인을 받는다. 완료 이후 들어오는 입력은 거부한다(재개하면 다시 받는다, 아래 "상차 재개"). ASN 대비 차이가 있으면 사유 선택이 필수이다. 사유는 공통코드 드롭다운(재고 부족(결품), 차량 적재 공간 부족, 타 차량 이관, 예정 외 차량(무지시), 상차 중 파손 발견, 기타)에서 고르며, "기타"를 고르면 텍스트 입력이 필수이다. 무지시 상차는 전량이 차이이므로 "예정 외 차량"을 선택한다. 상차완료와 함께 **상차확인서(실적 번호 + 바코드)**가 발행되며, 이 문서가 거래명세서 역할을 한다.

**상차 재개 (v1.5):** 상차완료 뒤 스캔을 빠뜨린 품목이 있거나, 다른 차량에 들어가지 않아 이 차량으로 옮겨 실어야 하는 경우를 위한 기능이다. 상차완료만으로 확정하면 검수 기준(상차완료 실적)에 없는 품목은 품목 불일치로 반송되기 때문이다.

- **주체·조건:** 같은 화주사의 **PDA 상차담당**이, 그 차량의 **입고검수가 시작되기 전**에만 재개할 수 있다. 검수가 시작된 뒤에는 재개할 수 없고 차이는 검수에서 처리한다.
- **사유:** 재개 사유는 필수이며 공통코드 드롭다운으로 고른다(예: 스캔 누락, 타 차량 이관, 추가 적재, 기타 — 기타는 텍스트 필수). 재개 시각·처리자·사유를 이력으로 남긴다.
- **재개 후:** 상차 실적은 작업중으로 돌아가고 기존 입력은 그대로 유지된다. 추가 입력은 상차 입력 규칙(C5)을 그대로 따른다. 다시 상차완료할 때 작업 인원·품목 합계 확인과 차이 사유 선택(C6)을 처음부터 다시 받는다.
- **상차확인서:** 번호는 그대로 두고 **차수**를 1 올려 표시한다(예: LD-20261111-0001 · 2차). 이전 차수로 인쇄한 종이 확인서는 무효이며 재인쇄한다. 검수는 번호로 시작하고 DB의 최신 차수 수량을 기준으로 하므로, 바코드는 차수와 관계없이 쓸 수 있다.
- **승인되지 않은 새 품목**은 재개로 실을 수 없다. 당일 ASN 품목 규칙(C5)이 그대로 적용되므로, 입고예정 등록 → 승인 → 별도 ASN(같은 차량번호 가능)으로 처리한다.

### ⑤ 입고예정 조회 (3PL·화주사, Web)

조회 기준은 두 가지이다. 하나는 승인 기준 품목별 조회, 다른 하나는 ASN·상차 기준 차량별 조회이다. 두 조회 모두 입고현황(검수·확정 진행)과 입고예정별 잔량을 함께 보여 준다.

### ⑥ 입고검수 · 확정 · 자동 배분 (3PL 입고검수자 PDA / 시스템)

검수자는 상차확인서 바코드, 상차지시서 바코드, 차량번호 중 하나로 검수를 시작한다. 그러면 해당 차량의 **상차완료 확정 수량**(재개한 경우 최신 차수)을 DB에서 불러온다. 검수 시작 조건은 **상차완료 상태인 차량 실적**뿐이다. 상차 재개로 작업중이 된 차량은 다시 완료할 때까지 검수를 시작할 수 없다.

| 이상 유형 | 처리 | 재고 반영 |
|---|---|---|
| 훼손·오염 | 품목 스캔 후 이미지 N장(최소 1장) 촬영, 반송 | 미반영 |
| 수량 불일치 | 실수량을 정확히 입력한 뒤 입고 (입고를 막지 않음) | 실수량만 반영 |
| 품목 불일치 | 반송 | 미반영 |

**작업자 잠금은 두지 않는다(v1.5, D22).** 상차와 같이 한 차량을 여러 검수자가 동시에 검수할 수 있고, 입력 한 건은 "추가로 센 수량" 한 행(작업자·시각)으로 쌓인다. 확정 전까지는 본인 입력(사진 포함)만 정정·취소할 수 있다.

예정 목록에 있지만 실물이 없는 품목은 검수자가 직접 **0(미도착)**으로 입력할 수 있다. 종료 단위는 **차량 1대 = 검수 확정 1회**이다. 확정 버튼을 누를 때 입력되지 않은 라인이 남아 있으면 경고창으로 목록을 보여 주고, "돌아가서 스캔" 또는 "남은 라인 전부 0 처리" 중 하나를 고르게 한다. **시스템이 미입력 라인을 임의로 0 처리하지 않는다.** 데이터에는 "검수자가 확인하고 0으로 입력함" 표시를 남겨 "실제로 없었다"와 "검수를 빠뜨렸다"를 구분한다. 검수 차이·반송 사유도 공통코드로 선택한다. 확정 후에는 수정할 수 없고, 적치 시작 전까지만 입고취소 역전표로 되돌린다.

검수가 확정되면 시스템이 **입고예정 자동 배분**을 수행한다(5장). 배분 결과 입고예정의 잔량이 0 이하가 되면 그 순간 **입고완료로 자동 종료**하고, 0 미만이면 초과로 함께 기록한다. 잔량이 남으면 **부분입고**로 유지한다.

### ⑦ 잔량 종결 · 일마감 (3PL 운영담당, Web)

**잔량 종결:** 잔량이 남은 입고예정(승인·부분입고)은 자동으로 닫지 않는다. 날짜를 넘겨도 열려 있으며, 이후 입고되는 물량도 자동 배분으로 잔량을 채운다. 3PL은 미종결 목록에서 입고예정별 경과일을 확인한다. 더 이상 입고되지 않는다고 판단하면 **잔량 종결**을 실행하며, 사유(미도착, 화주사 요청 등)가 필수이고 건별·일괄 처리가 모두 가능하다. 종결은 3PL만 할 수 있다. 화주사가 잔량을 더 보내지 않으려 할 때는 전표에 "잔량 종결 요청" 메모만 남긴다. 기준 경과일이 지난 미종결 건은 알림을 보낸다.

**일마감:** 매일 3PL이 실행하며, **당일 검수 확정 실적을 확정**하는 기능이다. 전표를 닫는 기능이 아니다. 정산·일별 수불은 전표 상태가 아니라 확정된 검수 수량 기준으로 집계하므로, 미종결 전표가 있어도 일마감에는 영향이 없다. 일마감 화면에는 미종결 입고예정 목록을 함께 보여 준다. 승인 전 상태(승인대기·반려)로 입고예정일이 지난 건은 실물이 오가지 않았으므로 일마감 시 **기한경과 취소**로 정리한다.

**업무일·기한경과 기준 (v1.5):**

- **업무일:** "당일"은 달력 날짜가 아니라 센터별 **업무일 시작 시각**(기본 06:00)부터 다음 날 그 시각 전까지이다. 검수 실적은 확정 시각이 속한 업무일 실적으로 귀속한다. 예: 06:00 시작 센터에서 새벽 2시에 확정한 실적은 전날 업무일 실적이다. 새벽 입고분이 날짜로 갈라지지 않게 하기 위함이다.
- **승인 이후 건은 막지 않는다:** 승인·부분입고 건은 입고예정일이 지나도, 일마감 뒤에도 그대로 ASN·상차·검수할 수 있다(전표를 닫지 않는 원칙). 실적은 실제 검수 확정한 업무일로 잡힌다.
- **기한경과 취소 시점:** 승인 전 건만 대상이며, 입고예정일 + **유예 영업일**(센터별, 기본 1)이 지난 업무일의 일마감 때 대상이 된다. 3PL이 승인을 늦게 처리한 건이 바로 취소되지 않게 하기 위함이다. 일마감 화면에서 취소 대상 목록을 먼저 보여 주고 3PL이 확인한 뒤 실행한다.
- **영업일:** 센터의 **정기 휴무 요일**과 **휴무일**(공휴일·센터 휴무)을 뺀 날이다. 토·일을 일괄로 쉬는 날로 보지 않으며(주말 운영 센터가 있음), 센터마다 정기 휴무 요일을 고른다(기본 없음).
- 업무일 시작 시각·유예 영업일·정기 휴무 요일은 센터 기준정보에서 센터별로 관리한다.

## 5. 수량 규칙

### 5-1. 잔량

잔량 = 승인수량 − 정상입고 누계 − 반송 누계

반송은 해당 전표에서 종결한 수량이므로 처리된 것으로 본다. 수량 차이로 기록된 부족분은 나중에 들어올 수 있으므로 잔량에 남긴다.

### 5-2. 검수 확정 시 자동 배분

![[04-자동배분규칙_v1.0.png]]

검수 라인의 수량이 어느 입고예정 라인을 채우는지 규칙으로 정한다. 같은 입력이면 누가 언제 처리해도 같은 결과가 나와야 하므로(재현성) 사람이 판단하지 않는다.

1. **1단계:** 원 ASN 라인이 가리키는 입고예정 라인에 먼저 채운다. 상한은 그 라인의 ASN 분배수량 잔량이다.
2. **2단계:** 남은 수량은 같은 화주사의 **미종결 입고예정** 중, 해당 품목이 ASN으로 분배된 라인에 **승인 시각이 오래된 순서**로 채운다. 상한은 각 라인의 ASN 분배수량 잔량이다.
3. **3단계:** 그래도 남으면 초과로 기록한다.

무지시 상차분은 원 ASN이 없으므로 바로 2단계부터 배분한다. 배분 결과는 배분 테이블에 (검수 라인, 입고예정 라인, 배분수량, 배분 단계)로 저장한다.

**예시** (IP-0001: A100·C100·F100 / IP-0002: A100·C30·F80, 모두 ASN 분배수량 = 승인수량)

| 실적 | 1단계 | 2단계 | 결과 |
|---|---|---|---|
| ASN-001 A 50 | IP-0001 A ← 50 | - | IP-0001 A 50/100 |
| ASN-011 A 100 | IP-0002 A ← 100 | - | IP-0002 A 100/100 |
| 무지시 차량 A 50 | 없음 | IP-0001 A 잔량 50 ← 50 | IP-0001 A 100/100 |
| ASN-002 C 50 | IP-0001 C ← 50 | - | IP-0001 C 50/100 |
| 무지시 차량 C 50 | 없음 | IP-0001 C 잔량 50 ← 50 | IP-0001 C 100/100 |
| ASN-003 F 90 | IP-0001 F ← 90 | - | IP-0001 F 90/100 |
| ASN-012 F 90 | IP-0002 F ← 80 (상한) | 남은 10 → IP-0001 F 잔량 10 | IP-0001 F 100/100, IP-0002 F 80/80 |

## 6. 정합성 체크 규칙

| No | 시점 | 체크 규칙 | 위반 시 |
|---|---|---|---|
| C1 | 입고예정 저장·수정 | 마스터 품목 미매칭 0건, 수량 > 0. 화주사 수정·취소는 승인대기·반려 상태에서만 | 저장 차단 |
| C2 | 승인·반려 | 조회 시점 version = 현재 version일 때만 처리. 일괄 처리는 건별 판정. 반려 사유 필수, 반려본 스냅샷 생성, 재저장 시 차수 +1, 승인 시 승인 차수 기록 | 처리 차단 |
| C3 | 승인 건 취소 | 승인 후 수정 불가. 취소는 3PL만, 후행 전표(ASN·검수) 없을 때만, 사유 필수, 최종 상태 | 취소 차단 |
| C4 | ASN 분배 | 승인·미종결 입고예정만, 라인별 분배 합계 ≤ 승인 잔량, 화주사 일치. 모든 화주사 ASN 필수 | 초과 분배 차단 |
| C5 | 상차 입력 | 같은 화주사 당일 ASN 등록 품목만(외 품목 차단). 당일 ASN 합계 초과는 경고 + 사유. 입력 1건 = 추가수량 1행(작업자·단말·시각). 완료 전 본인 입력만 정정 | 품목 차단 / 경고 |
| C6 | 상차완료·재개·검수 시작 | 상차완료 시 작업 인원·품목 합계 확인, 이후 입력 거부. ASN 대비 차이 시 사유코드 필수(기타 시 텍스트 필수). 상차 재개는 같은 화주사 PDA 상차담당만, 진행·확정 검수가 없을 때만, 사유 필수. 재완료 시 차수 +1. 검수 시작은 상차완료 차량 실적만 | 완료 불가 / 재개 차단 / 검수 시작 차단 |
| C7 | 검수 확정 | 스캔 품목 ∈ 기준 실적(불일치 시 반송). 정상 + 반송 = 기대 + 차이. 미입력 라인이 있으면 확정 불가 → 경고 후 스캔 또는 명시적 0 확정(0 확인 표시 저장). 훼손 반송 이미지 ≥ 1장. 검수·배분·입고예정 누계·상태를 단일 트랜잭션으로 갱신 | 전체 롤백 |
| C8 | 자동 배분 | 5-2 규칙 고정 적용. 라인별 배분 합계 = 검수 라인 수량. 잔량 ≤ 0 → 입고완료 자동 | 전체 롤백 |
| C9 | 잔량 종결·일마감 | 잔량 종결은 3PL만, 사유 필수. 일마감은 당일(센터 업무일) 검수 확정 실적 확정 + 승인 전 건 중 입고예정일 + 유예 영업일이 지난 건 기한경과 취소(대상 목록 확인 후 실행). 승인 이후 건은 대상 아님 | 처리 차단 |
| C10 | 전표 취소 공통 | 역순 취소 원칙: 후행 전표가 있으면 선행 전표 취소 불가. 입고취소 시 배분·누계 역반영 | 취소 차단 |
