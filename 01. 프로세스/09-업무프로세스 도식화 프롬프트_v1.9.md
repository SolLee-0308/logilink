# 프롬프트 본문

--- 시작 ---

너는 물류(3PL) 업무 프로세스를 도식화하는 업무 분석가다. 아래 "LogiLink 입고 업무프로세스 v1.9" 내용을 바탕으로 업무프로세스 도식을 Mermaid 코드로 만들어 줘.

## 1. 목적

- 3PL 센터의 입고 업무 전체(화주사 입고예정 등록 ~ 3PL 입고검수 확정·자동 배분 ~ 입고예정 종료)를 한눈에 보이게 그린다.
- 보는 사람: 3PL 운영담당, 화주사 담당자, 개발자. 업무 담당자가 "누가, 언제, 무엇을 눌러, 어떤 상태가 되는지"를 바로 알 수 있어야 한다.
- 기준은 정의서 **v1.9(2026-11-14 확정)**이다. 특히 최근에 추가된 **상차 재개, 출차, 입차·입차 취소, 검수 시작 = 첫 입력, 입고 대기, 입차·검수 진입 방법**은 빠뜨리지 않는다.

## 2. 만들 도식 (4개, 각각 별도 Mermaid 코드 블록)

| 번호 | 도식 | Mermaid 형식 | 핵심 |
|---|---|---|---|
| 1 | 전체 업무 흐름 (스윔레인) | `flowchart TB` + 주체별 `subgraph` | 주체별 레인, 단계 ①~⑦, 분기·예외 흐름 |
| 2 | 입고예정 상태 전이 | `stateDiagram-v2` | 승인대기·반려·승인·부분입고·입고완료·종결·취소 |
| 3 | 차량 1대의 흐름 (상차 → 출차 → 입차 → 검수) | `stateDiagram-v2` | 상차 재개, 출차 3가지 구분, 입차 취소, 도착·검수 대기 / 검수중 |
| 4 | 입차·검수 진입 판단 (PDA) | `flowchart TD` | 스캔 / 번호 정확 입력 / 일부 입력 / 목록 선택에 따른 분기 |

## 3. 주체(스윔레인)

| 레인 | 시스템 | 하는 일 |
|---|---|---|
| 화주사 담당자 | Web | 입고예정 등록·수정·취소·재요청, ASN 등록·취소 |
| 화주사 상차담당 | PDA | 상차등록(지시·무지시), 상차완료, 상차 재개, 출차 |
| 3PL 운영담당 | Web | 입고 승인·반려, 승인 건 취소, 잔량 종결, 일마감 |
| 3PL 입고검수자 | PDA | 입차, 입차 취소, 입고검수, 검수 확정, 입고취소(역전표) |
| 시스템 | - | 자동 배분, 입고완료 자동 종료, 출차 시스템 처리(입차 때·일마감 때) |

## 4. 단계별 업무 내용

**핵심 원칙**
- 모든 단계는 시작 트리거와 종료 시점·종료 상태가 명확하다.
- 확정된 전표는 고치지 않고 앞으로만 진행한다. 변경분은 차이 기록이나 새 전표로 처리한다.
- 모든 화주사는 ASN 등록과 상차등록을 반드시 거친다. 당일 ASN에 없는 품목은 실을 수 없다.
- 차량(ASN·상차 실적) : 입고예정 = N : M (라인 단위 연결).

**① 입고예정 등록 (화주사, Web)**
- 등록 방식 3가지: 직접 입력(품목 찾기), 엑셀 업로드, 카카오톡·이메일 이미지 AI 판독(저장 전까지 초안).
- 품목 마스터와 매칭되지 않은 줄은 사용자가 직접 매칭하고, 진짜 신규 품목만 "품목 등록 요청"으로 보낸다. 저장 시 미매칭 0건이어야 한다.
- 저장 → 상태 **승인대기**. 3PL 처리 전까지 화주사가 수정·취소 가능.

**② 입고 승인 (3PL 운영담당, Web)**
- 승인 또는 반려(반려 사유 필수). 화면을 연 뒤 화주사가 수정했으면 처리를 막는다(version 비교).
- 반려 → 화주사가 고쳐 재저장 → 차수 +1, 다시 승인대기.
- 승인 후에는 수정 불가. 입고 자체가 취소되면 3PL이 **승인 건 취소**(후행 전표가 없을 때만, 사유 필수, 최종 "취소").

**③ ASN 등록 (화주사, Web)**
- 승인·미종결 입고예정을 차량별로 나눠 담는다 → 저장과 동시에 **상차지시서(바코드)** 발행.
- 상차 시작 전까지만 ASN 취소 후 다시 만들 수 있다.

**④ 상차등록 (화주사 상차담당, PDA)**
- 지시 상차: 상차지시서 바코드 스캔으로 시작. 무지시 상차: 차량번호를 입력해 시작(ASN 없음).
- 여러 작업자가 동시에 입력(작업자 잠금 없음). 같은 화주사의 당일 ASN 품목만 입력 가능, 수량 초과는 경고와 사유만 받음.
- **상차완료**: ASN 대비 차이가 있으면 사유 필수 → **상차확인서(바코드)** 발행.
- **상차 재개**: 지시 상차만, **출차 전**까지, 사유 필수 → 작업중으로 돌아가 추가로 싣고 다시 상차완료(상차확인서 번호 유지, 차수 +1). 무지시 상차는 재개 불가.
- **출차**: 상차담당이 차량이 떠날 때 [출차]를 누른다. 되돌리기 없음, 출차 후 재개 불가.
  - [출차]를 빠뜨리면 시스템이 저장한다: 3PL이 그 차량을 입차할 때 → "입차 처리(시스템)", 도착 센터 일마감 때(전날까지 상차완료한 차량만) → "일마감 처리(시스템)".

**⑤ 입고예정 조회 (3PL·화주사, Web)** — 상태를 바꾸지 않는 조회. 도식 1에는 참고 노드로만 표시.
- "입고 대기" = ASN에 담겼지만 아직 검수 확정 전인 수량. 차량별 6단계로 보여 준다: 상차 전 → 상차중 → 출차 대기 → 운송 중 → 도착·검수 대기 → 검수중.

**⑥ 입차 · 입고검수 · 자동 배분 (3PL 입고검수자 PDA / 시스템)**
- **입차**: 차량 도착 시 상차확인서·상차지시서 스캔 또는 차량번호 입력. 상차완료 차량이고 도착 센터가 검수자 소속 센터일 때만. 입차 시 입고검수 전표 생성, 출차 기록이 없으면 "입차 처리(시스템)" 출차 함께 저장. 상태 = **도착·검수 대기**.
- **입차 취소**: 첫 입력 전까지만, 사유 필수, 검수 전표도 취소(출차 기록은 유지).
- **검수 시작** = 첫 입력(품목 스캔 또는 0(미도착) 입력) → 상태 **검수중**. 여러 검수자 동시 입력 가능.
- 이상 처리: 훼손·오염 → 사진 1장 이상 촬영 후 반송 / 수량 불일치 → 실수량 입력 후 입고 / 품목 불일치 → 반송.
- **검수 확정**(차량 1대 = 1회): 미입력 줄이 있으면 경고 → "돌아가서 스캔" 또는 "남은 줄 전부 0 처리" 중 선택. 차이·반송 사유는 확정 시 수량으로 시스템이 자동 지정.
- **자동 배분(시스템)**: 1단계 원 ASN의 입고예정 줄 → 2단계 같은 화주사 미종결 입고예정 중 승인 시각 오래된 순 → 3단계 그래도 남으면 초과 기록. 무지시 상차분은 2단계부터.
- 배분 결과 잔량 0 이하 → 입고예정 **입고완료**(자동), 잔량 남음 → **부분입고**.
- 확정 후 수정 불가. 적치 시작 전까지만 **입고취소 역전표** 후 재검수(배분도 되돌림).

**⑦ 잔량 종결 · 일마감 (3PL 운영담당, Web)**
- **잔량 종결**: 잔량 남은 입고예정(승인·부분입고)을 사유와 함께 닫음 → **종결**. 입고 대기가 남은 건은 종결 불가.
- **일마감**(매일): 당일(센터 업무일) 검수 실적 확정. 대상 목록을 먼저 보여 주고 확인 후 함께 처리:
  - 승인 전(승인대기·반려) 건 중 입고예정일 + 유예 영업일이 지난 건 → **기한경과 취소**
  - 출차·입차 기록 없이 전날까지 상차완료한 차량 → "일마감 처리(시스템)" 출차
- 업무일은 센터별 시작 시각(기본 06:00)부터 다음 날 그 시각 전까지. 승인 이후 건은 날짜가 지나도 막지 않는다.

## 5. 상태 정의 (도식 2·3에 사용)

**입고예정**
- 승인대기 → 승인 / 반려 / 취소(화주사 취소) / 취소(기한경과)
- 반려 → 승인대기(재저장, 차수 +1) / 취소(화주사 취소) / 취소(기한경과)
- 승인 → 부분입고 / 입고완료 / 종결 / 취소(3PL 승인 건 취소, 후행 전표 없을 때)
- 부분입고 → 입고완료 / 종결
- 입고완료·종결·취소 = 최종 상태

**차량(상차 실적 + 입고검수)**
- 작업중 → 상차완료 (상차확인서 발행)
- 상차완료 → 작업중 (상차 재개: 지시 상차만, 출차 전만)
- 상차완료 → 출차 (사람 / 입차 처리(시스템) / 일마감 처리(시스템))
- 상차완료(출차 전 또는 후) → 도착·검수 대기 (입차)
- 도착·검수 대기 → 입차 취소 (첫 입력 전, 사유 필수)
- 도착·검수 대기 → 검수중 (첫 입력)
- 검수중 → 검수확정 → 자동 배분
- 검수확정 → 입고취소(역전표, 적치 시작 전만)
- 참고: 출차·입차는 DB에서 상태가 아닌 기록(시각·처리자·구분)이지만, 도식 3에서는 업무 흐름이 보이게 단계로 그린다. 이 점을 도식 아래 한 줄로 적어 줘.

## 6. 입차·검수 진입 규칙 (도식 4에 사용)

| 입력 | 동작 |
|---|---|
| 바코드 스캔(상차확인서·상차지시서) | 그 차량으로 바로 진입: 입차 전이면 입차 후 검수 화면, 이미 입차했으면 그 차량 검수 화면(새 입차 아님) |
| 번호를 끝까지 정확히 입력, 일치 1건 | 스캔과 같이 바로 진입 |
| 번호 일부 입력(2자 이상) 또는 정확히 입력했지만 여러 건 일치 | 후보 목록 → 검수자가 고름. 입차 전 차량을 고르면 확인 창 후 입차 |
| 첫 화면 "입차 전" 목록에서 선택 | 확인 창("입차") 후 입차 (바코드 훼손·서류 없을 때 보조 수단) |
| 일치 대상 없음 | "입차할 수 있는 차량이 없습니다" 안내 |

## 7. 그리기 규칙

- 노드 이름은 한국어 업무 용어 그대로 쓴다(승인대기, 상차완료, 입차 처리(시스템) 등). 영어로 바꾸지 않는다.
- 노드 ID는 영문·숫자(예: `P1`, `LOAD_DONE`), 표시 글자는 `["한국어"]`로 감싼다. 괄호·특수문자가 있는 글자는 반드시 큰따옴표로 감싸 문법 오류를 막는다.
- 모양: 시작·끝 = `([ ])`, 사람이 하는 일 = `[ ]`, 판단 = `{ }`, 시스템 자동 처리 = `[[ ]]`, 문서 발행(상차지시서·상차확인서) = `[/ /]`.
- 정상 흐름은 실선 `-->`, 예외·되돌림(반려, 상차 재개, 입차 취소, 입고취소)은 점선 `-.->`과 라벨로 구분한다.
- 시스템 자동 처리 노드는 `classDef`로 색을 다르게 한다(예: 시스템 = 회색, 예외 = 주황, 최종 상태 = 진한 테두리).
- 도식 1은 너무 복잡해지지 않게 단계 ①~⑦과 주요 분기만 넣고, 세부 규칙은 노드 옆 짧은 라벨(10자 안팎)로만 쓴다.
- 이 내용에 없는 단계·상태·규칙은 지어내지 않는다. 애매하면 도식에 넣지 말고 마지막 "확인 필요" 목록에 적는다.

## 8. 출력 형식

1. 도식마다 `### 도식 N. 제목` → 한두 문장 설명 → Mermaid 코드 블록 순서로 쓴다.
2. 마지막에 "확인 필요" 목록(있으면)과, 각 도식이 위 단계·상태를 빠짐없이 담았는지 스스로 점검한 표(단계/상태 | 반영 도식 | 반영 여부)를 붙인다.
3. 코드가 mermaid.live에서 그대로 그려지는지 문법을 한 번 더 점검하고 내보낸다.

- 화주사 공유용: "화주사 레인 관점에서 화주사가 하는 일과 받는 결과만 남긴 도식을 따로 만들어 줘."
- 다른 형식: "같은 내용을 BPMN 2.0 기준 레인·이벤트·게이트웨이 표로 정리해 줘." 또는 "draw.io에서 열 수 있는 XML로 만들어 줘."
