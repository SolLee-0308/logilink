# LogiLink 가상 센터 구역·동선·시나리오 정의서 v0.1

> 목적
> 정의서 v1.4의 입고 흐름과 자동 배분 규칙을 **움직이는 화면**으로 보여 주는 포트폴리오용 데모를 만든다.
> 화면의 모든 움직임은 v1.4의 상태값과 규칙(C1~C10, 5-2)에서 나와야 한다. 규칙에 없는 움직임은 넣지 않는다.

### AI 오피스 레이어 원칙

- **AI 캐릭터는 정의서에 있는 AI 기능만 쓴다.** v1.4에 정의된 AI 기능은 **AI 판독**(카카오톡·이메일 이미지 → 입고예정 초안) 하나다.
- AI 판독 결과는 **저장 전까지 초안**이다(①). 캐릭터 말풍선도 "초안"으로 표시하고, 저장은 화주사 담당자가 한다.
- 자동 배분은 AI가 아니라 **고정 규칙**이다(5-2 "사람이 판단하지 않는다"). 캐릭터 이름은 "시스템 · 자동 배분"으로 쓰고, AI처럼 표현하지 않는다.

## 5. 시나리오 1 — "현장 변동이 있었던 날" (MVP)

정의서 5-2 예시와 자동배분규칙 v1.0 도식의 3장 예시를 그대로 쓴다. **최종 결과가 정의서 예시표와 같아야 한다.**

### 5-1. 기초 데이터 (정의서 예시)

| 입고예정 | 품목·승인수량 | 승인 순서 |
|---|---|---|
| IP-0001 | A 100 · B 100 · C 100 · D 100 · E 100 · F 100 | 먼저 승인 (2단계에서 우선) |
| IP-0002 | A 100 · C 30 · D 10 · F 80 | 나중 승인 |

| 차량 | 구분 | 실제 상차 |
|---|---|---|
| ASN-001 | 지시 | A 50 · B 100 |
| ASN-002 | 지시 | C 50 · D 100 |
| ASN-003 | 지시 | E 100 · F 90 |
| ASN-011 | 지시 | A 100 · C 30 |
| ASN-012 | 지시 | D 10 · F 90 |
| 무지시 차량 | 무지시 | A 50 · C 50 |

전제: 같은 화주사 1곳, 같은 센터. 정의서 예시대로 **ASN 분배수량 = 승인수량**. 검수 결과는 상차 수량과 같다(이상 없음).

## 6. 시나리오 2 — 예외 흐름 (제안, MVP 이후)

시나리오 1에는 반려·반송·0 확인·잔량 종결이 나오지 않는다. 다음 항목을 담은 별도 시나리오를 제안한다. **수량과 사례는 Sol 확정 전까지 정하지 않는다.**

| 다룰 규칙 | 정의서 근거 |
|---|---|
| 반려 → 재저장(차수 +1) → 승인 | ②, C2, D6 |
| 승인 직전 화주사 수정 → version 불일치로 처리 차단 | C2, D1 |
| 훼손·오염 반송 (사진 1장 이상) | ⑥, C7 |
| 미도착 품목 0 확인 / 미입력 라인 경고 | ⑥, C7, D15 |
| 부분입고 유지 → 경과일 → 잔량 종결(사유 필수) | ⑦, C9, D17 |

## 9. 디자인 방향

### 9-1. 콘셉트

**"관제 화면의 신뢰감 + AI 오피스의 친근함"**
바탕은 차분한 관제(디지털 트윈) 화면으로 두고, 사람·AI 캐릭터와 말풍선에서만 AI 오피스의 친근한 표현을 빌려 온다. 채용 담당자가 봤을 때 "장난감"이 아니라 "업무 규칙을 보여 주는 화면"으로 읽혀야 한다.

### 9-2. 시각 스타일 비교

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **A. 아이소메트릭 유지 (추천)** | 기존 좌표계·레이어 재사용, 캐릭터·말풍선만 AI 오피스 느낌으로 | 기존 자산 재사용, 업무 화면 톤 유지, 단일 HTML로 가벼움 | 유행 도구와 생김새가 같지는 않음 |
| B. 픽셀아트 전환 | 유행하는 픽셀 오피스 그대로 | 첫인상에서 "요즘 그거"로 바로 인식 | 기존 자산 폐기, 기획자 포트폴리오에서 가벼워 보일 위험, 앱 CI와 동떨어짐 |
| C. 혼합 | 맵은 아이소메트릭, 캐릭터만 픽셀 | 유행 요소 일부 | 두 스타일이 섞여 완성도가 떨어져 보임 |

### 9-3. 색

앱 CI(`tokens.css`)와 같은 의미 체계를 쓴다. 시뮬레이터의 색이 앱 화면과 같은 뜻이어야 한다.

| 쓰임 | 토큰 | 값 |
|---|---|---|
| 바탕 | `--bg` / `--surface` | #FFFFFF / #FAFAFB (밝은 테마. 기존 어두운 바탕은 폐기) |
| 구조물·글자 | `--ink`, `--line` | #161616, #ECECEF |
| 선택·포커스 | `--violet-500`~`700` | "지금 보고 있는 것"에만 (CI 규칙 그대로) |
| 입고예정 상태 7개 | `--st-*` | 승인대기·반려·승인·부분입고·입고완료·종결·취소 배지를 앱과 같은 색으로 |
| 배분 1단계 / 2단계 | (신규 2색) | 자동배분규칙 v1.0 도식의 파랑 / 진한 청록 계열을 이어 씀 |
| 예외(반송) | `--danger`, `--warn-*` | 반송·차이에만 |
| AI 판독 | `--violet-50` 면 + `--info-text` 글자 | AI 캐릭터 말풍선만. 초안이라는 뜻의 점선 테두리 |

포트폴리오 페이지에 넣을 때는 바깥 틀(제목·설명)만 포트폴리오 토큰(라임 = LogiLink)을 쓰고, 시뮬레이터 안쪽은 앱 CI를 유지한다. 라임은 포트폴리오에서 "지금 하는 일"을 뜻하므로 시뮬레이터 안에서는 쓰지 않는다.

### 9-5. 레이아웃

| 영역 | 내용 |
|---|---|
| 상단 바 | 제목, 시나리오 선택, 막 표시(1 입고예정 ~ 6 마감), 재생 제어, 시나리오 시계 |
| 가운데 | 물리 맵 (Z1~Z7) |
| 오른쪽 | 입고예정 보드(L1) 위 + 이벤트 로그 아래 |
| 하단 자막 | 지금 일어난 일과 적용된 규칙 한 줄. 예) "ASN-012 F 90 → IP-0002에 80(상한), 남은 10은 2단계로 IP-0001에" · `5-2` |

반응형은 포트폴리오 기준(1320 / 1060 / 760px)을 따르고, 노트북 1269×669에서 한 화면에 들어오게 한다. 760px 이하에서는 보드를 맵 아래로 내리고 맵 라벨을 숨긴다.

### 9-6. 움직임

- 차량·팔레트는 동선(F1~F8)을 따라서만 움직인다.
- 검수 확정 순간이 **유일한 강조 장면**이다. 배분 토큰이 보드로 날아가 진행 막대를 채우고, 2단계 배분은 색을 바꿔 눈에 띄게 한다.
- 상태가 바뀌면 보드 배지가 바뀌고 이벤트 로그에 한 줄이 쌓인다.
- 동작 줄이기 설정(`prefers-reduced-motion`)에서는 이동 없이 상태만 바뀐다.
- 정의서에 없는 숫자(KPI·처리 시간·인원 수)는 만들지 않는다. 배치·시각 같은 예시값은 기존처럼 "예시값" 점선 칩으로 표시한다.

## 10. 작업 순서

1. 이 정의서 검토·Q1~Q4 확정
2. 정지 화면: 새 구역 Z1~Z7 + L1 배치 (디자인 확인)
3. 엔진: `reduce` + `allocate` 이식 + 5-3 자동 대조 (화면 없이 먼저 결과 검증)
4. 움직임: 막 1~6 연결, 재생 제어
5. 반응형·동작 줄이기·포트폴리오 삽입
