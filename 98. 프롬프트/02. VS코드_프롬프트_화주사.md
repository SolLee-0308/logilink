# 작업 요청: 기준정보 – 화주사 화면 개편 + 목록형 기준정보 조회/편집 분리 패턴

## 배경
기준정보 > 화주사(/master/clients)를 검토했고, 결정 사항을 반영하려고 한다. 함께 정한 "조회/편집 분리" 패턴은 센터 등 다른 목록형 기준정보 화면에도 같이 적용한다.
- 기준 문서: `C:\Users\solle\OneDrive\문서\Obsidian Vault\PetProjects\3. 로지링크-3차\02. 프로세스\01-입고 업무프로세스 정의서_v1.4.md`
- 개념 정리: 같은 볼트의 `01. 기본\03. 개념 정리.md` (화주사는 상차지시서·상차확인서의 발송인)

## 진행 방식
1. 먼저 현재 코드(스키마, 화주사·센터·사용자·역할 화면, 공통 컴포넌트, 시드)를 읽고 **변경 계획과 영향 범위를 먼저 보여줘.** 내가 확인한 뒤에 구현해.
2. 이력은 기존 공통 변경 로그(tb_change_log)를 그대로 쓴다. 별도 _HIS 테이블은 만들지 않는다.
3. DB 변경은 Prisma 마이그레이션, 시드도 함께 갱신.
4. 끝나면 변경 파일 목록과 확인 방법을 정리해줘.

## 1. 공통 UI 패턴: 조회와 편집 분리

### 1-1. 목록형 기준정보 (목록 + 우측 패널)
| 동작 | 화면 |
|---|---|
| 목록에서 행 선택 | 우측 패널에 **조회 전용** 상세. 값은 입력칸이 아닌 텍스트로 표시. 하단에 `최종 변경 · 이력 보기` 유지 |
| 패널의 **[수정]** | **편집 모달**을 연다. 여는 순간 최신 데이터와 version을 다시 조회한다 |
| 목록 상단 **[+ 등록]** | 같은 편집 모달을 빈 상태로 연다 |

- [수정]·[+ 등록] 버튼은 **수정 권한이 있는 사용자에게만 보인다** (권한 없으면 버튼 자체를 숨김).
- 편집 모달: 넓은 모달, 2열 배치, 구역 제목으로 섹션 구분. 하단 [취소] [저장]. 저장 버튼은 변경 사항이 있을 때만 활성.
- 저장하지 않은 변경이 있는 상태에서 모달 닫기·ESC·다른 행 선택·페이지 이동 시 "저장하지 않은 변경 사항이 있습니다. 닫을까요?" 확인.
- 저장 성공 시 모달을 닫고 목록·패널을 갱신하고, 성공 토스트를 띄운다.
- version 충돌 시 기존 규칙대로 저장을 막고 최신 내용을 다시 불러온다.
- **공통 컴포넌트로 만들고 적용 대상: 화주사, 센터, 사용자·역할.** 운영 설정 등 그 밖의 목록형 기준정보는 적용 가능 여부를 표로 제안만 해줘 (품목·품목 등록 요청·휴무일은 이번 제외).

### 1-2. 단건 기준정보 (회사 정보)
- 페이지 기본은 조회 모드(텍스트 표시). 우측 상단 [수정]을 누르면 같은 자리에서 입력 폼으로 전환되고, 하단 [취소] [저장]이 나타난다.
- 이탈 확인, version 재조회, 권한별 버튼 숨김은 1-1과 동일.

## 3. 화주사 코드 규칙과 자동 추천

### 3-1. 형식
- **영문 대문자 2자 + 숫자 2자, 총 4자 고정** (예: `DO01`). 다른 곳에서 화주사 코드를 프리픽스로 쓰기 위해 길이를 고정한다.
- **숫자 2자 = 같은 영문 2자 안에서의 순번** (01부터). 예: 다온생활 `DO01`, 이후 도원상사 `DO02`.
- 순번은 '사용 안 함' 화주사까지 포함해서 센다. 한 번 쓴 코드는 다시 쓰지 않는다.
- 중복 불가, 등록 후 수정 불가 (기존 규칙 유지). 같은 영문 2자에서 99를 넘으면 "이 약어는 더 이상 쓸 수 없습니다. 다른 약어를 입력하세요."

### 3-2. 입력 방식 (등록 모달)
- 화주사 코드 입력칸은 **영문 2자 입력칸 + 숫자 2자 표시**로 나눈다.
  - 영문 2자: 화주사명을 입력하면 **자동 추천해서 채운다.** 사용자가 바꿀 수 있다.
  - 숫자 2자: 시스템이 자동으로 붙인다(사용자 수정 불가). 영문을 바꾸면 그 약어 기준 다음 순번으로 다시 계산해서 보여 준다 (예: `DO` + `02 (예정)`).
- 사용자가 영문 칸을 직접 수정한 뒤에는 화주사명을 바꿔도 **자동 추천으로 덮어쓰지 않는다.** 칸 옆에 "추천값 다시 적용" 링크를 둔다.
- 최종 순번은 **저장 시점에 서버에서 확정**한다. 동시에 같은 약어로 등록하면 유니크 제약으로 막고 다음 순번으로 재시도한 뒤, 확정된 코드를 저장 완료 메시지로 알려준다.

### 3-3. 자동 추천 알고리즘
1. 화주사명에서 법인 표기 제거: `(주)`, `㈜`, `주식회사`, `(유)`, `유한회사`, 공백
2. 첫 두 글자를 각각 영문 1자로 변환해 이어 붙인다.
   - **한글 음절**: 초성을 로마자 첫 글자로 변환
     - ㄱG ㄲK ㄴN ㄷD ㄸT ㄹR ㅁM ㅂB ㅃP ㅅS ㅆS ㅈJ ㅉJ ㅊC ㅋK ㅌT ㅍP ㅎH
     - 초성이 ㅇ이면 **중성**으로 결정: ㅏㅐ→A, ㅓㅔㅡㅢ→E, ㅗㅚ→O, ㅜ→U, ㅣ→I, ㅑㅒㅕㅖㅛㅠ→Y, ㅘㅙㅝㅞㅟ→W
   - **영문**: 대문자로 변환해 그대로 사용. 화주사명이 영문 단어 여러 개면 각 단어의 첫 글자
   - **숫자**: 그대로 사용하지 않고 건너뛴다 (첫 글자는 반드시 영문)
3. 검증 예시 (기존 데이터와 일치해야 함)
   - 다온생활 → `DO`, 한빛식품 → `HB`, 새봄유통 → `SB`, 오션푸드 → `OS`, 그린마켓 → `GR`
   - 단, 기존 데이터는 그린마켓 `GM`, 오션푸드 `OF`처럼 사람이 정한 약어이다. 추천은 출발점일 뿐이며, 이런 경우 사용자가 바꾸면 된다.
4. 알고리즘은 순수 함수로 분리하고 단위 테스트를 작성해줘 (위 예시 + 법인 표기, 영문명, ㅇ 초성 케이스).

### 3-4. 기존 데이터 이관 (개발 단계이므로 시드 갱신)
- DO → `DO01`, GM → `GM01`, HB → `HB01`, OF → `OF01`, SB → `SB01`
- 화주사 코드를 참조하는 품목·사용자·전표 등 모든 FK를 함께 갱신. 영향 받는 테이블 목록을 계획 단계에서 먼저 보여줘.

## 4. '사용 안 함' 전환 규칙
- 해당 화주사에 **미종결 전표**(2-2 요약 기준)가 1건이라도 있으면 전환을 막는다: "미종결 전표 N건이 있어 사용 안 함으로 바꿀 수 없습니다." + 전표 유형별 건수 표시
- '사용 안 함' 화주사 소속 사용자는 **로그인을 차단**한다: "사용이 중지된 화주사의 계정입니다. 관리자에게 문의하세요." (로그인 이력에 차단 사유 기록)
- 다른 화면의 화주사 선택 목록(드롭다운·필터)에서 '사용 안 함' 화주사는 기본 제외한다. 조회 필터에서는 '사용 안 함 포함' 옵션으로 볼 수 있게 한다.
- 다시 '사용'으로 바꾸는 것은 제한 없음.

## 6. 화면 규칙 패널(?) 추가 문구
- 화주사는 상차지시서·상차확인서의 발송인입니다. 법인 정보(상호·사업자번호·대표자·주소)가 출력물에 들어갑니다.
- 화주사 코드는 영문 2자 + 순번 2자이며, 다른 데이터의 프리픽스로 쓰이므로 등록 후 바꿀 수 없고 한 번 쓴 코드는 다시 쓰지 않습니다.
- 화주사는 1개 이상의 센터를 이용합니다. 미종결 전표가 있는 센터는 이용 센터에서 뺄 수 없습니다.
- 미종결 전표가 있으면 사용 안 함으로 바꿀 수 없습니다. 사용 안 함 화주사의 사용자는 로그인할 수 없습니다.
- 등록·수정은 3PL 관리자만 할 수 있습니다.
- 기존 문구(D7 ASN·상차 필수, 코드 수정 불가, 삭제 금지, 동시 수정 방지)는 유지.

- [ ] 화주사·센터·사용자·역할: 행 선택 시 패널이 조회 전용(텍스트)이고 [수정]을 누르면 편집 모달이 열린다
- [ ] [+ 등록]과 [수정]이 같은 모달을 쓰고, 저장하지 않은 변경이 있으면 닫을 때 확인창이 뜬다
- [ ] 회사 정보: 조회 모드 → [수정] → 편집 → [저장]/[취소]
- [ ] 3PL 운영담당 로그인 시 [+ 등록]·[수정] 버튼이 보이지 않고 API도 거부된다
- [ ] 화주사명 입력 시 영문 2자가 자동 추천되고, 직접 수정하면 더 이상 덮어쓰지 않는다
- [ ] 숫자 2자가 같은 약어 기준 다음 순번으로 붙고, 저장 시 서버에서 확정된다
