# 웹 재구성·기준정보 1차·웹 시뮬레이터 대화 요약

## 1. 요약

2026-10-31에 프로세스·IA 문서 개정에 맞춰 **웹 화면을 처음부터 다시 구성**했다. 기반(Next.js 설정·Supabase 연결·RLS·Auth.js 로그인)은 남기고, 옛 DB 구조·업무 로직·화면은 백업한 뒤 지웠다. 새 문서(IA 02·03·04) 기준으로 **공통 틀·로그인·기준정보·사용자·이력** 화면을 만들었고, 테마는 **딥 틸·민트**로 바꿨다. 이어서 상단 화주사·센터 드롭다운을 없애고 고정 상단 바를 만들었으며, 최신 문서에 따라 **3PL 운영사·화주사 화면 분리, 메뉴명 정리, 코드·사유 보강, 대표 바코드 규칙**을 반영했다. 마지막 작업은 브라우저 점검 도중 사용량 한도로 중단되어 **점검 결과 보고가 남아 있다**. 같은 날 별도 대화에서 **웹 시뮬레이터 1단계(정지 화면)**도 완성했다.

검수용 계정은 `admin`(관리자 역할 3개)과 `hanbit`(한빛식품, 기본 조회만)이고 비밀번호는 이전과 같다. 검수용 데이터는 센터 2, 화주사 2, 위치 6, 품목 5개이며, 용인 센터는 일부러 일반 보류 위치를 비워 "확인 필요" 표시가 보이게 했다.

## 4. 최신 문서 반영 (3PL 운영사·메뉴명·코드·바코드)

| 구분 | 반영 내용 |
| --- | --- |
| 3PL 운영사 | `Operator`(운영사·법인 정보), `CenterOperator`(센터 소속·유효기간) 신설. 운영사 1:N 센터, 같은 기간에 센터는 운영사 1개. 기존 센터 2개는 "기본 운영사"에 자동 소속 |
| 권한 범위 | 3PL 사용자는 운영사+센터, 화주사 사용자는 화주사+접근 가능 센터(`UserScope.operatorId` 추가) |
| 화면 구조 | 3개 탭(화주사·센터·관계) 폐기 → **운영 조직**(운영사·소속 센터) / **화주사**(상세의 이용 센터에서 관계 관리) |
| 기준정보 메뉴 | 운영 조직 · 화주사 · 품목 · 물류 위치 · 검수 정책 · 예외·보류 정책 · 코드·사유 |
| 전체 메뉴명 | 입고 계획·출하 / 입고 운영 / 예외·보류 / 결과·마감 / 시스템 관리(사용자·권한·승인 위임·이력·감사)를 짧은 업무명으로 정리, 옛 주소는 새 주소로 리다이렉트 |
| 코드·사유 | 운영자 관리 코드·시스템 고정 코드·사유 코드로 구분, 24개 그룹 등록(`src/lib/code-catalog.ts`). 보관온도대는 시스템 고정 코드. 확정 문서에 값이 없는 코드는 `미확정` 표시 |
| 바코드 | `ItemBarcode.isPrimary`·`barcodeType` 추가. 대표 바코드 정확히 1개, 활성 바코드 최소 1개. 기존 데이터는 품목·단위별 가장 먼저 등록된 바코드를 대표로 지정 |
| 마이그레이션 | `20261031100000_operator_barcode_codes` |

기준 문서는 프로젝트 내부 최신본(10/31 15:06~15:10 개정)이다. 확정 문서는 `00. 기본/01~03`, `01. 프로세스/01·02`이고, `01. 프로세스/03. 상태 전이`와 `00. 기본/04. (CH) 기준정보·운영정책`은 검토중 보조 근거로 썼다.

## 6. Sol의 주요 결정

| 구분 | 결정 내용 |
| --- | --- |
| 재구성 방식 | 기반은 유지하고 DB 구조·업무 로직·화면은 새 문서 기준으로 재구성. 옛 내용은 작업 폴더에서 치우고 백업에만 보관 |
| 설계 근거 | IA 02(화면 ID)·03(UI 레퍼런스)·04(화면 구성 체크리스트). (CH) 문서는 확정 근거로 쓰지 않음. 외부 옵시디언 경로는 참고하지 않음 |
| 테마 | 딥 틸 `#20343B`, 민트 `#73B8AE`, 배경 `#F4F7F7`(차콜·로즈 대체). 민트 위 흰 글자 금지 |
| 역할 | 최소 3개(MASTER_ADMIN·PERMISSION_ADMIN·AUDITOR)부터 |
| 기준정보 범위 | 확정 문서 범위의 필드만. W-MD-03은 등록·조회만 |
| 화면 틀 | 상단 화주사·센터 드롭다운 폐기, 각 화면 조회조건에서 선택. 고정 상단 바에 메뉴 경로·화면명·화면 ID·도움말, 오른쪽은 화면 단위 행위 |
| 화면 ID | 검수 기간에만 표시, 운영 전 `SHOW_SCREEN_ID=false` |
| 정리 문서 | `개발 후 처리 목록.md`는 옛 내용을 지우고 새로 작성 |
| API 키 | Claude API 키 발급은 모든 개발 단계 완성 후. 그 시점에 Claude가 먼저 언급 |
| 웹 시뮬레이터 | 1단계는 정지 화면만. 이동·타이머·상태 전이는 2단계 전까지 구현 금지, 새 구역·상태코드·KPI 수치 생성 금지 |
