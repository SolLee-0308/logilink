# 2차 재구성·공통 UI·기준정보 DB 대화 요약

## 1. 요약

2026-11-02에 개발을 **두 번째로 처음부터 다시 시작**했다. 백업 없이 이전 코드(`03. 개발`, `03. 개발_백업_20261031`)와 Supabase의 옛 로지링크 테이블을 모두 지웠고, `.env`(Supabase 접속정보)만 남겼다. 새 CI 가이드(바이올렛·검정 사이드바, 로고 B. 박스)와 승인 대기 시안을 기준으로 **공통 UI(토큰·사이드바·공통 컴포넌트)**를 먼저 만들었다. 이어서 Sol의 요청으로 승인 대기보다 **기준정보를 먼저, DB와 함께** 개발했다. 기준정보는 **사이드바 하위 메뉴 8개**(회사 정보·화주사·품목·품목 등록 요청·사유 코드·사용자·역할·휴무일·운영 설정)로 완성했고, 품목은 **단위 환산·단위별 복수 바코드·별칭·보관 온도대·유통기한/로트 관리**까지 갖췄다. 브라우저 자동 점검은 모두 통과했다. **다음 작업은 승인 대기 화면을 DB와 연결해 만드는 것**이다.

### 4-2. DB (Supabase, Prisma 7)

| 구분 | 테이블 |
| --- | --- |
| 조직 | `tb_company`(1건), `tb_center`, `tb_client`, `tb_user` |
| 품목 | `tb_item`, `tb_item_uom`, `tb_item_barcode`, `tb_item_alias` |
| 품목 등록 요청 | `tb_item_req`, `tb_item_req_his` |
| 코드·설정 | `tb_code_group`, `tb_common_code`, `tb_setting`, `tb_holiday` |
| 이력 | `tb_change_log` (기준정보 공통 변경 이력) |

모든 테이블에 RLS를 켜서 Supabase 공개 API로는 접근할 수 없고, 새 테이블에도 자동 적용된다. 마이그레이션은 3개(`20261102000000_init`, `20261102000100_constraints_rls`, `20261102010000_item_uom_alias_company_holiday`)이다. 초기 데이터는 `npx prisma db seed`로 언제든 다시 넣을 수 있다(전체 초기화).
