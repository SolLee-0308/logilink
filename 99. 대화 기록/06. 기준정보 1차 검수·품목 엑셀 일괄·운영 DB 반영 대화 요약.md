# 기준정보 1차 검수·품목 엑셀 일괄·운영 DB 반영 대화 요약

## 1. 요약

2026-11-04 오전에는 GitHub 최신 소스를 내려받아 **기준정보 1차 검수**를 진행했다. 중심은 품목이었다. 실무에서는 품목을 엑셀로 한꺼번에 등록하는 일이 많아 **엑셀 일괄 등록(3PL)·엑셀 일괄 요청(화주사)** 을 만들었다. 몇 차례 의견을 주고받은 끝에 메뉴를 **3PL '품목 관리' / 화주사 '품목 조회'** 로 나누고, 화주사는 품목을 직접 등록하지 않고 **품목 등록 요청**으로만 보내도록 정리했다. 등록 화면은 **단건 / 엑셀 탭** 하나로 합쳤다. 품목 등록 요청은 **넓은 목록 + 별도 상세 화면**으로 바꾸고, 처리하면 다음 요청이 바로 열리게 했다. 사용자는 **한 사람이 역할 여러 개**를 가질 수 있게 했고, 휴무일은 **목록 화면으로 되돌린 뒤 공공데이터 불러오기**를 붙였다. 화주사 로그인 후 첫 화면은 **임시로 품목 조회**로 바꿨다(나중에 대시보드로 변경). 오전 작업은 **브랜치에 커밋하고 운영 DB(Supabase)에 마이그레이션을 반영**했다.

오후에는 **화주사 입고예정 등록 화면**을 새로 만들었다. 메뉴 '입고예정 등록'에서 **직접 입력·엑셀 업로드·이미지 AI 판독** 세 가지로 등록하고, 엑셀·판독 원문은 품목 마스터와 맞춰 **확인 필요** 줄만 고치게 했다. AI 판독은 API 키가 없어 **예시 판독**으로 동작한다. 이어 Sol 검수에 따라 **승인 대기를 목록 + 별도 상세 화면**으로 바꾸고, **반려 버튼을 붉은색**으로, **카드 테두리·머리 띠로 영역을 분명하게** 했다. 품목·화주사가 많아질 것에 대비해 **품목 찾기 창·화주사 찾기 창**(서버 검색)을 만들고, 조회조건을 **입고예정일 기간(달력) + [입고예정번호]/[품목] 두 칸**으로 바꿨다. 화주사 계정에는 센터가 없어 **사용자별 기본 센터**를 새로 두었다. 저녁에는 화면 다듬기를 이어서, **입고예정 상세(화주사)도 승인 상세와 같은 구성**(번호 옆 상태 배지, 입고예정 정보 2단, [이력 보기])으로 맞추고, **입력칸 안내 글자를 연하게**, 목록 위 **"행을 누르면…" 설명문을 삭제**, **등록 버튼은 화면 제목 줄 오른쪽 위에 보라색**으로 옮겼다. 오후·저녁 작업은 **아직 커밋·운영 DB 반영 전**이다.

밤에는 오후·저녁 작업 커밋을 확인한 뒤 `feat/master-data-review` 브랜치를 **push하고 `main`에 병합**했다. 이어 **화주사 ASN 등록**을 만들었다. 차량 기준정보는 두지 않고 **ASN마다 차량번호를 직접 입력**하며, ASN 1건은 **차량 1대 · 한 화주사 · 한 센터**로 정했다. 등록 화면에서는 승인된 입고예정을 입고예정별로 묶어 보여 주고, 라인마다 **남은 수량까지만** 이번 차량에 담게 했다. 저장하면 **상차지시서(Code128 바코드)** 가 함께 발행되고, 상세 화면에서 A4로 인쇄한다. ASN 작업은 `feat/asn-entry`에 커밋해 `main`에 병합했고, 운영 DB 마이그레이션 3건도 반영했다.

### 4-3-3. ASN 규칙 (밤)

| 항목 | 내용 |
| --- | --- |
| 담을 수 있는 것 | 같은 화주사 · 고른 센터 · 승인/부분입고 입고예정 라인. 입고예정일과 출고일이 달라도 됨(어제 잔량도 오늘 차량에) |
| 남은 수량 | 승인 − 종결 − 취소되지 않은 ASN 지시수량. 입고예정 라인 단위로 입력, 기준 단위 환산도 저장. 같은 라인에 동시에 저장하면 라인을 잠가 한쪽만 저장되고, 다른 쪽은 "남은 수량이 바뀌었습니다 → 다시 불러오기" |
| 차량번호 | 필수, 공백 제거·대문자로 저장. 번호판 모양이 아니면 저장은 되지만 확인 안내 |
| 번호 | `ASN-YYYYMMDD-NNNN`, 상차지시서 `LO-YYYYMMDD-NNNN` (등록일 기준) |
| 취소 | 등록(상차 시작 전) 상태만, 사유 코드(입고예정과 같은 '취소' 그룹) 필수. 상차지시서도 함께 취소, 담았던 수량은 다시 담을 수 있음. ASN은 수정하지 않고 취소 후 재등록 |
| 미종결 | 등록·상차중 ASN은 화주사 사용 안 함·이용 센터 제외를 막는 미종결 건수에 포함 |

## 6. 공공데이터 API 키 발급 (휴무일 불러오기)

휴무일 화면의 [공공데이터 불러오기]는 **공공데이터포털의 "한국천문연구원_특일 정보" API**로 공휴일을 가져온다. 대체공휴일과 임시공휴일도 이 API에 반영되기 때문에, 비공식 데이터(구글 캘린더 공휴일 피드, 개인이 올린 GitHub 데이터)는 쓰지 않는다. 키가 없으면 불러오기 버튼을 눌러도 오류 안내만 나온다.

### 6-1. 발급 절차

1. [data.go.kr](https://www.data.go.kr)에 회원가입하고 로그인한다.
2. 검색창에 **"한국천문연구원_특일 정보"** 를 검색해 오픈 API 상세로 들어간다.
3. **[활용신청]** 을 누르고 활용 목적(예: "물류 입고관리 시스템 휴무일 관리")을 적어 신청한다. 개발계정은 보통 바로 자동 승인된다.
4. **마이페이지 › 개발계정**에서 신청한 API를 열고 **일반 인증키(Decoding)** 를 복사한다. Encoding 키를 넣어도 프로그램이 알아서 처리한다.

### 6-2. 키 넣기

| 환경 | 방법 |
| --- | --- |
| 로컬 개발 | `03. 개발/.env`에 `DATA_GO_KR_SERVICE_KEY=복사한키` 한 줄 추가 → dev 서버 재시작 |
| 운영 | 배포 환경의 환경변수에 같은 이름(`DATA_GO_KR_SERVICE_KEY`)으로 등록 |

`.env`·`.env.*` 파일은 git에 올라가지 않도록 설정되어 있다. 키는 채팅이나 문서에 붙여 넣지 않는다.

### 6-3. 쓰는 법과 주의

- **불러오기:** 휴무일 화면에서 [공공데이터 불러오기] → 연도와 센터를 고르고 실행한다.
- **겹치는 날짜:** 이미 휴무일이 있는 날짜는 건너뛰고, 같은 날 공휴일이 둘이면 이름을 합친다.
- **삭제와 복원:** 불러온 공휴일도 삭제할 수 있다. 같은 연도를 다시 불러오면 삭제한 공휴일이 복원된다.
- **다음 해 공휴일:** 정부 발표 뒤에 반영되므로, 연말에 다음 해를 한 번 불러오고 임시공휴일이 발표되면 다시 불러온다.
- **개발계정 제한:** 하루 호출 수 제한이 있지만 연 몇 번 불러오는 용도에는 충분하다. 활용 기간이 끝나기 전에 마이페이지에서 연장 신청한다.
- **검증 상태:** 아직 키가 없어 실제 API 호출은 확인하지 못했다. 키를 넣은 뒤 한 번 불러와 확인이 필요하다.

## 8. 결론

오전에는 **품목을 "3PL이 등록·관리하고 화주사는 조회·요청한다"는 구조로 정리**하고, 엑셀 일괄 등록·요청과 요청 검토 화면, 복수 역할, 휴무일 공공데이터 불러오기까지 마친 뒤 커밋·운영 DB 반영을 했다. 오후에는 **화주사 입고예정 등록(직접 입력·엑셀·AI 판독)** 을 만들고, Sol 검수에 따라 **승인 대기를 목록 + 상세 화면으로**, **화면 영역·반려 버튼을 분명하게**, **품목·화주사는 찾기 창으로**, **조회조건은 기간 + 번호/품목 두 칸으로**, **센터 기본값은 사용자별 기본 센터로** 바꿨다. 저녁에는 **입고예정 상세 구성 통일, 연한 안내 글자, 설명문 삭제, 보라색 등록 버튼**으로 화면을 다듬었다. 밤에는 브랜치를 **push·`main` 병합**하고, **화주사 ASN 등록(차량번호 직접 입력, 한 화주사·한 센터, 남은 수량까지 분배)과 상차지시서 인쇄**를 만들었다. 다음 대화에서는 **ASN 화면 검수**를 한 뒤 **PDA 상차등록**으로 넘어간다.
