# PDA 화면 재구성·입고검수(PDA)·운영 DB 반영 대화 요약

## 1. 요약

오늘 오후에는 **PDA 화면을 참고 UI(Pinterest 2건)에 맞춰 다시 구성**했다. 실제 PDA 크기(360 × 720)에 맞춰 글자·여백·버튼을 줄였고, PC 시연용 **PDA 테두리**와 **SPLASH**를 붙였다. 또 **역할별 PDA 메뉴**(상차담당: 상차등록·상차내역·대시보드 / 입고검수자: 입고검수·검수 내역·대시보드)를 확정해 만들었다.

이어서 **입고검수(PDA)**를 구현했다. 검수자가 상차완료 차량을 스캔해 품목별 정상·훼손 반송 수량을 쌓고, **검수 확정 한 번으로 자동 배분(5-2) → 입고예정 부분입고/입고완료 → ASN 입고완료 → 상차지시서 검수완료**까지 이어진다. 웹에는 ASN 상세 **입고검수 카드**와 입고예정 상세 **입고·반송·잔량** 열을 붙였다. 점검을 모두 통과한 뒤 **커밋, `main` 병합, push, 운영 DB 반영**까지 마쳤다.

마지막으로 아직 만들지 않은 **입고예정 조회(정의서 ⑤)** 화면 구성을 논의했고, **결정 2건이 남아 있다(6장).**

### 4-5. 입고검수 규칙 (`src/domain/rcv-rules.ts`, `src/server/rcv/service.ts`)

| 규칙 | 내용 |
| --- | --- |
| 시작 | 상차완료 차량·소속 센터만, 진행·확정 검수는 상차 실적당 1건(DB 부분 유일 인덱스) |
| 입력 | 잠금 없음, 검수 행을 잠근 뒤 1행씩 쌓음, 본인 입력만 취소·정정, 기대수량 초과는 경고만 |
| 확정 | 확인 화면 이후 새 입력이 있으면 막음, 미입력 품목은 경고 → 명시적 0(0 확인 표시), 차이·반송 품목 사유 필수(기타는 상세), 훼손은 사진 1장 이상 |
| 자동 배분 | 1단계 원 ASN 라인(상한 = ASN 라인 지시 − 이미 배분) → 2단계 같은 화주사·센터 미종결 입고예정 중 ASN 분배된 라인(승인 시각 순, 상한 = ASN 분배 − 이미 배분, 승인 잔량 이내) → 3단계 초과. 정상 먼저, 반송이 이어서. 같은 화주사 배분은 advisory lock으로 줄 세움 |
| 상태 | 잔량 0 이하 → 입고완료, 남으면 부분입고, ASN 입고완료, 상차지시서 검수완료, 이력 "입고검수 확정" — 한 트랜잭션 |

### 4-6. DB (마이그레이션 `20261105100000_rcv`)

`tb_rcv_h`(헤더)·`tb_rcv_d`(품목 합계)·`tb_rcv_input`(입력 행)·`tb_rcv_image`(사진)·`tb_rcv_alloc`(배분) 5개 테이블, enum `RcvStatus`·`RcvKind`·`RcvAllocKind`, `PlanAction`·`AsnAction`에 `RECEIVE` 추가, CHECK 제약 6개, 부분 유일 인덱스. RLS는 이벤트 트리거로 자동 적용. 권한 `inspection`(3PL 입고검수자).

## 6. 남은 일 — 다음 대화에서 먼저 결정할 것

**입고예정 조회(정의서 ⑤) 화면 구성** — 메뉴만 있고 화면은 없다. 정의서 ⑤: "승인 기준 품목별 조회 / ASN·상차 기준 차량별 조회, 두 조회 모두 입고현황과 입고예정별 잔량을 함께 보여 준다."

| No | 결정할 내용 | 선택지 | 추천 |
| --- | --- | --- | --- |
| 결정 1 | 품목별 탭 구성 | A. 품목 평면 목록(입고예정 × 품목 1행) / **B. 입고예정 1행 + 펼치면 품목 라인**(품목 검색 시 해당 라인 자동 펼침, 행은 진행률 %) / C. 입고예정 행만 + 품목은 상세에서 | **B** |
| 결정 2 | 차량별 조회 | **A. 정의서대로 차량별 탭**(차량 1행 + 펼치면 연결된 입고예정 라인·잔량, 오는 중 물량) / B. 탭 없이 품목별 탭에 "오는 중" 열 + 기존 ASN 상세 보강 | **A** (B도 실용적) |

함께 제안한 설계(추천안, 결정 1·2와 같이 확인 필요): Q1 화주사 담당자·3PL 관리자·운영담당 공통 메뉴 / Q3 조회 조건(입고예정일 기간·화주사·센터·상태·검색, 기본 미종결) / Q4 상세 = 라인별 입고·반송·잔량 + 배분 이력 + 처리 이력 / Q5 상세에 [승인 건 취소](3PL, 후행 전표 없을 때, 사유 필수) / Q6 승인 후 경과일 표시·기준 초과 강조(알림은 4단계).

그다음 순서: 입고예정 조회 → 4단계(입고취소 역전표·잔량 종결·일마감·입고검수 실적 웹 화면).

## 7. 결론

PDA는 실제 단말 크기에 맞춘 화면·시연 테두리·SPLASH·역할별 메뉴로 정리되었고, **입고검수(PDA)부터 자동 배분, 웹 반영, 운영 DB까지 완료**했다. 다음 대화에서는 **입고예정 조회 화면의 품목별 탭 구성(결정 1)과 차량별 조회 여부(결정 2)**를 먼저 정한 뒤 착수한다.
