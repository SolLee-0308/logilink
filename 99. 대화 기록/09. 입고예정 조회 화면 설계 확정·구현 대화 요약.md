# 입고예정 조회 화면 설계 확정·구현 대화 요약

## 1. 요약

지난 대화에서 남겨 둔 **입고예정 조회(정의서 ⑤)** 화면 결정 2건과 추천 설계 Q1~Q6을 모두 확정했다. 품목별 탭은 **입고예정 1행 + 펼치면 품목**(B안), 차량별 조회는 **같은 화면 안의 탭**(A안)으로 정했다. 탭 대신 메뉴를 둘로 나누는 안도 검토했지만 기존 "ASN·상차 현황"과 겹쳐서 기각했다.

확정한 설계대로 **목록·상세·3PL 승인 건 취소**를 구현했고, 서버 규칙·기존 규칙·단위 테스트·브라우저 점검을 모두 통과했다. 브랜치 `feat/plan-inquiry`에 **커밋했다**(`main` 병합·push는 아직). DB 구조 변경이 없어 운영 DB에 반영할 것은 없다. 남은 결정은 **경과일 기준** 1건이다(6장).

## 4. 만든 것

### 4-1. 목록 `/plans/inquiry` (`src/features/plans/inquiry/InquiryScreen.tsx`)

- 위쪽 요약 칸 **"경과 기준 초과 미종결 N건"**: 기간과 상관없이 세고, 누르면 해당 건만 걸러진다. [처음 조건으로] 링크.
- 탭: 품목별 / 차량별. 탭·기간·상태·화주사·센터가 바뀌면 서버에서 다시 조회하고, 번호·품목 검색은 받은 목록 안에서 바로 거른다. 조건은 주소에 남아 상세에서 [← 목록]으로 돌아오면 유지된다.
- **품목별 탭** 열: 입고예정일(D-day 또는 "n일 경과") · 입고예정번호 · 화주사(3PL만) · 센터(여러 센터일 때) · 품목 수 · 진행률 막대 · 오는 중/차량 수 · 승인 일시(승인 후 n일) · 상태 · [상세]. 펼치면 품목별 승인·오는 중·입고·반송·종결·잔량·진행률.
- **차량별 탭** 열: 출고일 · 차량(기사) · ASN번호 · 화주사 · 센터 · 입고예정 · 줄 수 · 입고현황(오는 중 / 입고 %) · 상태. 펼치면 입고예정번호(상세 링크)·품목·지시·오는 중·입고·반송·입고예정 잔량.
- 상태 선택지: 품목별 = 미종결(기본)·전체·승인·부분입고·입고완료·종결·취소(승인 건 취소) / 차량별 = 미입고(기본)·전체(취소 제외)·등록·상차중·상차완료·입고완료.
- 한 번에 1,000건까지 보이고, 넘으면 기간을 줄이라고 안내한다.

### 4-2. 상세 `/plans/inquiry/[id]` (`InquiryDetailScreen.tsx`)

- 입고예정 정보(화주사·센터·입고예정일·경과·승인·진행률·차량 수·메모)
- 품목별 입고현황(승인·오는 중·입고·반송·종결·잔량·진행률, 입고예정 단위로 표시)
- 실린 차량(ASN) / 배분 이력(검수번호·차량·ASN·배분 단계·입고/반송·수량) / 처리 이력
- 3PL에게만 **[승인 건 취소]**: 후행 전표가 있으면 버튼이 꺼지고 이유를 안내한다. 취소된 건은 사유·처리자·일시를 표시한다.

### 4-4. 임시안 (U46)

1. 조회 대상은 승인 기준(승인·부분입고·입고완료·종결·승인 건 취소). 승인 전 건은 승인 대기·입고예정 등록 화면에서 본다.
2. 경과일은 입고예정일 다음 날부터 센다(미종결만). 운영 설정 '미종결 알림 기준 경과일'(3일) 이상이면 빨간색으로 강조하고, 승인 후 일수는 보조로 표시한다.
3. 진행률 = (입고 + 반송 + 종결) ÷ 승인.
4. 오는 중 = 입고 전 ASN(등록·상차중·상차완료)에 담긴 수량.
5. 승인 건 취소 = 승인 상태 + 취소되지 않은 ASN 0건 + 검수 배분 0건. 사유는 취소(CANCEL) 그룹을 쓰고, 기한경과(X04)는 일마감 자동 처리 전용이라 목록에서 뺀다.
6. 차량별 탭은 ASN만 보여 준다(무지시 상차·취소 ASN 제외). 입고·반송은 그 차량의 검수로 그 라인에 배분된 수량이다.

## 6. 남은 일 — 다음 대화에서 먼저 안내할 것

| No | 내용 |
| --- | --- |
| 1 | **개발 서버는 운영 DB(Supabase)에 연결된다.** `npm run dev`는 `.env` 설정을 그대로 쓰므로 점검용 로컬 DB가 아니다. 새로 만들거나 바꿀 테이블이 없어 입고예정 조회 화면은 바로 열린다. 다만 상세에서 **[승인 건 취소]를 누르면 운영 데이터가 실제로 취소되고 되돌릴 수 없으니** 시험할 때 주의한다. |
| 2 | 화면 확인 순서: 왼쪽 메뉴 **입고 계획 › 입고예정 조회** → 품목별·차량별 탭, 행 펼침, 상세 화면 |
| 3 | **결정 필요 — 경과일 기준:** Q6은 "승인 후 경과일"이었지만 운영 설정 설명은 "입고예정일로부터"다. 지금은 입고예정일 기준으로 강조하고 승인 후 일수는 보조로 표시했다. 유지할지, 승인일 기준으로 바꿀지 정해야 한다. |
| 4 | **병합·push 여부:** `feat/plan-inquiry`는 커밋 완료. 화면 확인 뒤 Sol이 정하면 `main` 병합 → push (마이그레이션 없음) |

그다음 순서: 4단계(입고취소 역전표·잔량 종결·일마감·입고검수 실적 웹 화면).

## 7. 결론

입고예정 조회 화면은 **확정한 설계대로 구현했고 모든 점검을 통과했다.** `feat/plan-inquiry`에 커밋했고, `main` 병합·push는 Sol의 화면 확인 뒤로 미뤘다. 다음 대화에서는 **개발 서버가 운영 DB에 연결된다는 점과 승인 건 취소 주의 사항**을 먼저 안내한 뒤, **경과일 기준과 병합·push 여부**를 묻는다.
