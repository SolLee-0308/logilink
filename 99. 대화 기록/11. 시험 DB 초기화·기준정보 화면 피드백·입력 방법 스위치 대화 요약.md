# 시험 DB 초기화·기준정보 화면 피드백·입력 방법 스위치 대화 요약

## 1. 요약

**시험 환경.** 대화 기록 10의 수정본을 커밋·push했다(`a6ed228`). Sol이 처음부터 시험해 보고 싶다고 해서 **로컬 시험 DB를 사용자·조직 정보만 남기고 비웠다**. 운영 DB(Supabase)는 건드리지 않았다.

**기준정보 화면 피드백.** 다음을 반영했다.

- **공통:** 등록 버튼 너비·자간, 드롭다운 화살표 여백, 날짜·시각 칸을 누르면 선택 창, 조회조건 칩을 연회색 묶음 + 흰 선택 칸으로 바꿈
- **기준정보 목록:** 센터·화주사·사유 코드·사용자 목록에서 '최종 변경' 열 삭제
- **화주사:** 담당자 칸 이름을 '업무 연락 담당자'로 바꾸고, 사업자등록번호 오류 문구를 자릿수 부족과 검증 숫자 불일치로 나눔
- **사업자등록번호 중복:** 11-03 결정대로 허용하되, 저장 전에 확인창을 띄움

**등록 화면.** 단건/엑셀 탭을 여러 번 시안으로 다듬었다(선택 카드 → 카드 머리 스위치 → 제목 줄 스위치). 최종안은 **화면 제목 줄 오른쪽의 연보라 '입력 방법' 스위치**이고, 세 화면(3PL 품목 등록, 화주사 품목 등록 요청, 입고예정 등록)에 적용했다. 상태 탭을 상태 색으로 칠하는 안은 Sol 결정으로 지금처럼 두었다.

**마무리.** `feat/1106-master-feedback2` 브랜치에 커밋했다(`09630f5`). DB 구조 변경이 없어 운영 DB 반영은 없다. **`main` 병합·push는 아직 하지 않았다.**

## 3. 시험 DB 초기화

**결정:** 사용자만 남기는 것은 구조상 불가능하다. 사용자 13명이 센터·화주사에 소속되어 있기 때문이다. 그래서 사용자와 소속 조직, 그리고 시스템이 동작하는 데 필요한 값은 남겼다. 화주사–센터 이용 연결과 휴무일은 Sol 선택으로 남겼다.

| 구분 | 테이블(건수) |
| --- | --- |
| 남김 | 사용자 13, 회사 1, 센터 3, 화주사 5, 화주사–센터 연결 7, 휴무일 9, 사유 코드 그룹 6·코드 31, 운영 설정 2 |
| 지움 | 품목(단위·바코드·별칭 포함), 품목 등록 요청·이력, 입고예정·반려본·이력·AI 판독, ASN·상차지시서·이력, 상차 실적, 입고검수, 변경 이력, 로그인 기록, 세션 |

- **실행 방식:** 실행 전에 남길 테이블이 지울 테이블을 참조하지 않는지, TRUNCATE에 걸린 트리거가 있는지 확인했다. 한 트랜잭션으로 지우고 번호 카운터도 초기화했다(`restart identity`). 접속 주소가 localhost가 아니면 멈추는 확인을 이중으로 넣었다.
- **비밀번호:** 남은 사용자의 비밀번호는 그대로이고, 세션을 지워 다시 로그인해야 한다.
- **이후 시험 기록:** 화면 점검 때문에 Claude가 `han.soyul`·`hb.minji`로 로그인해 로그인 기록·세션이 몇 건 생겼다. 저장한 업무 데이터는 없다.

## 5. 새 사용자 로그인 안내

Sol이 새로 만든 사용자로 마스터 비밀번호를 넣었는데 로그인이 되지 않았다. **오류가 아니다.** 마스터 비밀번호(`.env`의 `SEED_DEFAULT_PASSWORD`)는 시드 사용자 13명에게만 적용된다. 화면에서 등록한 사용자는 비밀번호 없이 만들어진다.

| 순서 | 할 일 |
| --- | --- |
| 1 | 3PL 관리자(예: `han.soyul`)로 기준정보 › 사용자·역할에 들어간다 |
| 2 | 새 사용자를 고르고 [비밀번호 초기화]를 누른다 |
| 3 | 한 번만 표시되는 임시 비밀번호를 복사한다 |
| 4 | 새 사용자로 로그인한 뒤 새 비밀번호로 바꾼다(변경 강제) |

로그인에 5번 연속 실패하면 계정이 잠기지만, [비밀번호 초기화]를 하면 잠금도 함께 풀린다.

**개선안(미정):** A. 사용자를 등록할 때 임시 비밀번호를 바로 발급(추천) / B. 등록 완료·상세에 "아직 비밀번호가 없습니다" 안내만 추가. Sol의 선택을 기다리고 있다.
