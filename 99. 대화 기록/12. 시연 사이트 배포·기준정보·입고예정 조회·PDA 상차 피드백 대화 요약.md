# 시연 사이트 배포·기준정보·입고예정 조회·PDA 상차 피드백 대화 요약

## 1. 요약

**시연 사이트.** 16:30 선생님 피드백을 위해 **Vercel + 시연 전용 Supabase 프로젝트**로 시연 사이트를 만들었다. 주소는 https://logilink-demo-six.vercel.app 이다. 운영 DB는 건드리지 않고, 시험 DB의 데이터를 시연 DB로 복사했다. 선생님용 계정 2개(`hb.minji` 화주사 담당자, `han.soyul` 3PL 관리자)만 시연 전용 비밀번호로 바꿨다. 선생님용 테스트 시나리오는 Claude Docs 문서로 만들었다.

**화면 피드백.** 기준정보(품목 등록 요청·품목 조회), 전체 공통(조회조건·탭·저장 실패 알림·메뉴), 입고예정 조회, ASN·상차 현황, PDA 상차 화면을 고쳤다. 입고예정 조회는 **상태 탭 + 보기 전환(입고예정별·차량별)** 으로 구조를 바꿨다(11-05 결정 대체).

**오류 수정.** 시험 서버(연결 1개)에서 입고예정 저장이 "처리하지 못했습니다"로 실패했다. 트랜잭션 안에서 밖의 연결로 설정값을 읽던 것이 원인이었고, 같은 문제를 화주사 수정에서도 찾아 함께 고쳤다.

**데모 반영.** 오늘 작업을 main에 병합(`d2e1b88`)하고 배포 브랜치 `deploy`(`339af13`)를 갱신해 시연 사이트에 올렸다.

## 2. 시연 사이트 배포

| 항목 | 내용 |
| --- | --- |
| 구성 | Vercel(프로젝트 `logilink-demo`) + 새 Supabase 프로젝트(시연 DB, 도쿄). 운영 Supabase와 별개 |
| 데이터 | 시험 DB 35개 테이블을 그대로 복사(세션 제외), 건수 모두 일치 |
| 접속 정보 | `03. 개발/.env.demo` (git 제외). Vercel 환경변수 = `DATABASE_URL`·`DIRECT_URL`·`AUTH_SECRET` |
| 배포 브랜치 | **`deploy`** = main의 `03. 개발` 폴더만 최상위로 둔 커밋. Vercel Root Directory 비움, Production Branch = `deploy` |
| 시연 계정 | `hb.minji`·`han.soyul`만 시연 비밀번호. 나머지 계정은 시험 DB와 같은 초기 비밀번호 |

배포하면서 막힌 점과 해결:

| 문제 | 원인 | 해결 |
| --- | --- | --- |
| 빌드 실패 `Invalid URL` 가능성 | DB 연결 코드가 빌드 중에도 `DATABASE_URL`을 읽음 | 환경변수 값에 따옴표·공백 없이 입력 |
| Turbopack 내부 오류(한글) | Linux에서 폴더명 `03. 개발`의 한글 처리 결함 | `vercel.json`에 `next build --webpack` |
| 서버 함수 이름 거부(공백) | 저장소 최상위 기준이라 함수 이름에 `03. 개발/`이 붙음 | 배포 전용 `deploy` 브랜치(폴더 내용을 최상위로) |
| 응답 지연 | Vercel 기본 리전이 미국 | `vercel.json` `regions: ["hnd1"]`(도쿄) |

배포 사이트에서 선생님 시나리오(요청 → 등록·반려 → 재요청)를 다른 계정(`gm.doyun`·`kim.haneul`)으로 점검했고(7/7), 점검 데이터는 시연 DB에서 지웠다.

## 3. 화면 피드백과 결정

### 3-1. 기준정보

| 화면 | 결정·반영 |
| --- | --- |
| 품목 등록 요청 · 엑셀 | 파일을 올린 뒤 드롭 영역 연보라, 단계 설명은 제목 옆 한 줄로 짧게, [다시 올리기]·[N건 요청(보라)]은 3단계 제목 줄 오른쪽 |
| 등록 화면 입력 방법 전환 | 입력한 내용이 있으면 확인창, [지우고 바꾸기]면 그 탭 내용 삭제(두 탭 내용이 동시에 남지 않음) |
| 품목 등록 요청 목록 | '원본' 조회조건 삭제(정의서 요구 아님), 원본 열은 **3PL 목록에만**, 바코드 열은 목록에서 삭제 |
| 요청 상세 | 처리 이력을 처리 결과 아래로(3PL 등록대기만 왼쪽 유지), [수정해서 다시 요청]·[다시 요청] 연보라 |
| 품목 조회 | 화주사 품목코드를 더 연한 회색 |

### 3-2. 전체 공통

| 항목 | 결정·반영 |
| --- | --- |
| 조회조건 높이 | 2줄(110px) 고정 |
| 메뉴 숫자 | **지금 내가 처리할 일만**. 화주사는 품목 등록 요청·입고예정 등록 옆에 **반려 건수 붉은 숫자**, 등록·승인대기 건은 숫자 없음 |
| 메뉴 순서 | 입고예정 등록 → 입고예정 조회 → ASN 등록 |
| 저장 실패 | 붉은 알림 6초 + 첫 오류 칸(없으면 오류 상자)으로 화면 이동 |
| 상태 탭 | **밑줄형**(선택 = 진한 글자 + 보라 밑줄). 11-06 "탭 색 변경 안 함"을 바꿈 |
| 경고 표시 규칙 | 요약 카드 대신 **경고할 건이 있을 때만 붉은 띠 + 해당 탭 ⚠N**(공통 부품 `AlertStrip`) |
| 메뉴 너비 | 228px → 208px |
| 기간 지우기 | 버튼 삭제, 달력 팝업의 [삭제] 사용 |

### 3-3. 입고예정 조회 (A안)

- 상태 탭(건수): 미종결 · 승인 · 부분입고 · 입고완료 · 종결 · 취소 · 전체. **승인 이후 건만**.
- 제목 줄 오른쪽 **보기** 스위치: 입고예정별 / 차량별(차량별은 ASN 상태 탭).
- 경과 기준 초과 미종결: 요약 카드 → 있을 때만 붉은 띠 + 미종결 탭 ⚠N, [이 건만 보기].
- 상태 탭은 다른 목록처럼 조회조건 아래. 펼침 화살표·[상세] 연보라.

### 3-4. ASN·상차 현황

- 출고일 지난 상차 대기: 있을 때만 붉은 띠 + 상차 대기 탭 ⚠N.
- 오늘·내일 출고: 출고일 옆 빠른 선택 [오늘 N대] [내일 N대].

### 3-5. PDA 상차

| 화면 | 결정·반영 |
| --- | --- |
| 대시보드 | 작업 중 주황 · 상차완료 초록 · 차이 있음 붉은 칸(상차할은 기본) |
| 상차 작업 | 머리 아래 구분선, 품목코드 + 품목명 한 줄(길면 옆으로 흐름), '아직 안 실음' 삭제, '일치 N/M품목'은 머리 상태 줄 일반 글자 |
| 입력 후 | 토스트 없음 → 해당 품목 줄로 이동·연보라 강조(커서는 스캐너 때문에 스캔 칸 유지) |
| 상차완료 확인 | 아래에서 올라오는 확인 창. 차이 품목 목록·차이 사유 선택 포함 |
| 상차확인서 | 품목 목록 대신 "ASN 대비 상차: 일치 N/M품목 · 부족 k" |

### 3-6. 보류 (개발 완료 단계에서 리마인드)

- **상차·검수 수량의 EA 기준**: 수량은 이미 기준 단위로 센다. 시험 품목 다수가 기준 단위 BOX·EA 환산 없음. 제안 = 품목 등록 규칙 "기준 단위 = 출고할 수 있는 가장 작은 단위" + "120 EA (= 10 BOX)" 표시.
- ANTHROPIC_API_KEY 발급.

## 7. 결론

시연 사이트(https://logilink-demo-six.vercel.app)를 만들어 오늘 오후 피드백까지 반영했다. 화면 규칙으로 **메뉴 숫자는 내가 처리할 일만, 경고는 있을 때만 붉은 띠, 상태 탭은 밑줄형**이 정해졌다. 입고예정 조회는 상태 탭 중심으로 바뀌었다.
