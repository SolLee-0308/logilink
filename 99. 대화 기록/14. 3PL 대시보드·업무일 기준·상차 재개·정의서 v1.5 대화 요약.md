# 3PL 대시보드·업무일 기준·상차 재개·정의서 v1.5 대화 요약

## 1. 요약

**결론.** 2026-11-11에 네 가지를 끝냈다. ① 3PL·화주사 웹 대시보드를 만들고 두 쪽 모두 첫 화면으로 바꿨다. ② 13번 기록에서 대기 중이던 일마감 기준 두 가지(업무일 기준 시각, 기한경과 취소 유예)를 결정하고, 센터별 정기 휴무 요일을 추가했다. ③ PDA 상차 작업 화면을 피드백대로 정리하고, 상차완료 뒤에도 검수 시작 전까지 다시 실을 수 있는 **상차 재개**를 만들었다. ④ 바뀐 규칙을 담은 **정의서 v1.5**를 작성했다. 마이그레이션 3개는 운영 DB에 반영했고, main에 병합해 push했다. 시연 사이트는 아직 반영하지 않았다.

**배경.** 일마감(4단계) 착수 전에 Sol이 현황을 볼 대시보드를 먼저 넣고 싶어 했다. 대시보드의 "오늘"을 세려면 업무일 기준이 필요해서 일마감 결정을 함께 했다. 이어서 Sol이 PDA 상차등록 화면을 검수하면서 화면 정리와 "상차완료 뒤 추가 적재" 문제를 제기했다.

"오늘"은 센터별 업무일 기준이다. 3PL 첫 화면을 승인 대기에서 대시보드로 바꿨고, 메뉴 맨 위 '현황' 그룹에 넣었다.

## 3-1. 화주사 대시보드 (같은 `/dashboard`, 역할로 나눔)

화주사 담당자가 로그인하면 품목 조회 대신 대시보드가 첫 화면으로 열린다. **자기 화주사 건만, 이용 센터 기준**으로 세며, 이용 센터가 2곳 이상이면 센터를 골라 본다. 3PL 대시보드와 같은 센터별 집계를 함께 쓰므로 같은 건이면 두 대시보드의 숫자가 항상 같다.

| 영역 | 내용 |
| --- | --- |
| ① 할 일 | 반려된 입고예정(붉게), 오늘 기한경과 취소(붉게), ASN 등록할 입고예정(차량에 담을 잔량이 남은 승인 건), 승인 대기(3PL 검토 중), 검수 중 차량, 반려된 품목 등록 요청(붉게). 누르면 해당 화주사 화면으로 이동 |
| ② 오늘 흐름 | 3PL과 같은 3묶음(입고예정·ASN 차량·검수 확정)을 내 건만 센다 |
| ③ 주의할 건 | 기한경과 승인 전 건, 출고일 지난 상차 대기, 오늘 검수 차이, 오래된 미종결 입고예정 |
| ④ 이용 센터 기준 | 센터별 업무일 시작 시각·일마감 시각·기한경과 유예·정기 휴무 |

3PL 화면과 일부러 다르게 만든 부분은 세 가지다.

| 차이 | 이유 |
| --- | --- |
| 기한경과 목록에 **유예 중 건까지** 보이고 건마다 취소 예정일을 표시한다(오늘 취소될 건은 붉은 "오늘 일마감") | 화주사가 마감 전에 3PL에 승인을 요청하거나 반려 건을 고칠 수 있게 |
| 일마감 카드 대신 **이용 센터 기준**을 보여 준다 | 일마감은 화주사가 하는 일이 아니다. 새벽 입고가 전날 실적으로 잡히는 이유를 화주사도 알 수 있게 |
| 화주사명 열을 뺐다 | 자기 건만 보인다 |

점검: 집계 점검 19건(3PL 9건, 화주사 10건 — 건수 DB 일치, 다른 화주사 건 없음, 이용 센터 범위, 링크가 화주사 화면으로 감) 통과, 단위 시험 68건 통과. 화주사(hb.minji)·3PL(han.soyul) 계정 모두 로그인 후 `/dashboard`로 가서 화면이 정상으로 열리는 것을 확인했다(임시 세션은 점검 후 삭제). 센터 고르기 점검은 시험 3PL 계정에 소속 센터가 있어 돌지 않았다.

## 5. 상차 재개 (정의서 v1.5 D20, U57)

**문제.** 상차완료 뒤에 스캔을 빠뜨린 품목이 있거나, 다른 차량에 안 들어가 이 차량에 실어야 하는 경우가 있다. 현행 규칙에서는 검수 기준이 "실은 수량 1 이상인 품목"뿐이라, 통째로 빠진 품목은 검수 때 **품목 불일치로 반송**된다.

**검토한 안.** A. 상차완료 취소(재개), B. 추가 상차 실적(확인서 2장), C. 검수에서 받아 주기(C7 변경). Sol이 **A안**을 골랐다.

| 결정 | 내용 |
| --- | --- |
| 조건 | 그 차량의 입고검수가 시작되기 전까지만 |
| 주체 | PDA 상차담당 (같은 화주사) |
| 사유 | 필수, 공통코드 LOAD_REOPEN (임시안 — 7장 참고) |
| 상차확인서 | 번호는 유지하고 **차수**를 표시한다(예: LD-… · 2차). 이전 차수로 인쇄한 확인서는 폐기하고 재인쇄한다 |
| 재개 후 | 작업중으로 돌아가고 기존 입력은 유지된다. ASN은 상차중, 상차지시서는 발행으로 되돌린다. 재완료할 때 차이 사유를 다시 고른다 |
| 새 품목 | 재개 대상이 아니다. 입고예정 등록 → 승인 → 별도 ASN(같은 차량번호 가능)으로 처리한다 |
| 기록 | 상차 처리 이력 TB_LOAD_HIS(완료·재개, 차수)와 ASN 이력(LOAD_REOPEN)에 남긴다. 웹 상차 실적 카드와 인쇄에 차수와 마지막 재개를 표시한다 |

시험 DB 1번 상차 실적으로 재개부터 재완료까지 12건을 점검해 모두 통과했고, 점검 뒤 원래 상태로 되돌렸다. 검수가 시작된 차량의 재개 차단은 시험 DB에 검수 건이 없어 실제로 돌려 보지 못했다(코드상 차단).

## 8. 운영 DB 반영·커밋·main 병합

| 마이그레이션 | 내용 |
| --- | --- |
| `20261111000000_center_business_day` | tb_center 업무일 시작 시각·기한경과 유예 영업일 |

## 10. 결론

일마감 기준(업무일·유예 영업일·정기 휴무)이 정해져 3PL·화주사 대시보드가 그 기준으로 "오늘"을 보여 주게 됐다. 두 대시보드는 같은 집계를 쓰고, 화주사는 자기 건과 이용 센터 기준만 본다. 상차완료 뒤 추가 적재는 검수 시작 전 **상차 재개**로 처리하고, 확인서는 같은 번호에 차수를 붙여 다시 발행한다. 이 규칙들은 정의서 v1.5에 반영했고, 운영 DB 반영과 main 병합·push까지 마쳤다. 시연 사이트는 아직 반영하지 않았다. 재개 사유 코드와 도식 갱신은 추후 다시 봐야 한다.
