# 대시보드 가독성·PDA 상차등록 통합·출차·입고검수 PDA 대화 요약

## 1. 요약

**결론.** 2026-11-12에 다섯 가지를 했다. ① 웹 대시보드의 가독성을 높였다(ASN 진행 막대, 0건 카드 접기). ② PDA **상차내역 메뉴를 상차등록에 합치고** 화면을 정리했다. ③ 상차 작업 화면을 상차 재개 규칙에 맞추고, **무지시 상차는 재개 불가, 재개는 출차 전까지**로 바꾸며 **출차** 단계를 새로 만들었다. 이 규칙은 **정의서 v1.6**에 반영했다. ④ ①~③을 main에 병합·push하고 **운영·시연 DB에 마이그레이션을 적용해 시연 사이트에 반영**했다. ⑤ 오후에는 **입고검수 PDA를 상차등록과 같은 UI로** 맞추고(검수 내역 메뉴 통합), 여러 검수자가 함께 셀 때 사유를 너무 일찍 묻는 문제를 고쳤다. ⑤는 별도 브랜치에 커밋했고 main 병합·시연 반영은 하지 않았다.

**배경.** Sol이 시험 DB(3001)에서 대시보드와 PDA 상차등록을 차례로 검수하며 피드백을 줬다. 상차 작업 화면 검수 중 "상차완료 뒤에도 다시 실을 수 있다"는 어제 규칙과 맞지 않는 문구·흐름이 드러났고, 일반 물류센터의 운영 방식을 확인한 뒤 출차 기준을 정했다.

## 2. 웹 대시보드 가독성 (3PL·화주사 공통)

| 영역 | 변경 |
| --- | --- |
| ② 오늘 흐름 | 오늘 출고 ASN 차량을 **한 줄 진행 막대**(상차 대기 → 상차중 → 검수 대기 → 입고완료, ASN 상태 배지 색) + "N대 중 M대 입고완료 · %" 요약 |
| ③ 주의할 건 | 건이 있는 카드만 펼치고 0건 카드는 "✓ 이상 없음" 한 줄로 모음 |
| ④ 일마감 / 이용 센터 | 매일 보는 값만 표에 두고 센터 설정값(업무일 시작·유예·정기 휴무)은 "센터 기준 보기"로 접음 |
| ① 할 일 | 0건 칸은 흐리게 |

추천했던 그래프 중 나머지(7업무일 추이 등)는 새 집계가 필요해 보류했다. **진행 막대는 시험·시연 DB 모두 오늘 출고 ASN이 0대라 아직 화면에 그려진 적이 없다**(안내 문구만 보임). A안(0대일 때도 빈 막대 틀 표시)·B안(시험 DB에 오늘 출고 ASN 추가) 결정이 남아 있다.

## 3. PDA 상차등록 통합

| 항목 | 결정 |
| --- | --- |
| 메뉴 | 상차담당 = 대시보드 · 상차등록 (상차내역 폐지, 예전 주소는 "완료" 보기로 이동) |
| 목록 형식 | 표(그리드)가 아니라 **카드 유지** (PDA 너비·장갑 터치 때문) |
| 검정 영역 | 스캔칸 그대로 + **날짜칩(오늘/MM-DD, 누르면 달력, 지난 날짜면 노랑) + 보기 버튼(전체·상차할·상차 중·완료, 건수) 한 줄**. 위 요약 줄은 삭제. 드롭다운 → 버튼 줄 → 공간 문제로 날짜와 한 줄(A안)로 바뀌어 왔다 |
| 날짜 규칙 | 상차 중은 날짜와 상관없이 항상, 오늘이면 출고일 지난 상차할 차량 포함, 완료는 상차일 |
| 카드 | 상차할 회색 · 상차 중 **연한 주황**(배지색 40% + 흰색) · 상차완료 **연한 연두** + 각 색의 왼쪽 띠. [상차 중]·[상차완료] 알약은 빼고 [출고일 지남]·[차이 있음]·[출차 전]만 |
| 진행 단계 | 카드 안 점은 체크 없는 10px 점 |
| PDA 대시보드 | 칸마다 아이콘(트럭·상자·체크·경고), 아이콘·이름 왼쪽 위·숫자 오른쪽 아래, 이름 "상차할 차량"·"상차 중" |
| 확인 창 위치 | PC 시연 틀에서 아래 확인 창이 단말기 몸체 아래에서 올라오던 문제를 화면 기준으로 고침(PDA 전체) |

## 4. 상차 작업 — 재개 규칙 정리와 출차 신설

**재개 문구 검수.** 상차완료 확인 창의 "완료하면 더 입력할 수 없습니다" 등 어제 규칙과 반대인 문구 6곳과 함께 손볼 곳 3곳을 고쳤다(재완료 차수 안내, 완료 화면 방금 발행/목록 조회 구분, 재개 시각·사유를 머리에, 목록 "재개 N차", 완료 화면 재조회).

**규칙 결정.**

| 결정 | 내용 | 근거 |
| --- | --- | --- |
| 무지시 상차 재개 불가 | 더 실을 물량은 새 무지시 상차로 | 예정 외 차량이라는 예외 위에 예외를 두지 않음, 다음 날 재개 시 당일 ASN 품목 기준이 바뀌는 문제 해소 |
| 재개 기간 = **출차 전** | 지시 상차 + 출차 전 + 검수 전 | 일반 물류센터는 문 닫기·봉인·서류 인계 후 출하 확정(출차)하면 기록을 다시 열지 않음. 차가 떠난 뒤 수량이 늘어나는 것 방지 |
| 출차 기록 | PDA 상차완료 화면 **[출차]**(확인 창, 되돌리기 없음). 메뉴 추가 없음, 목록 카드에는 버튼 없이 [출차 전] 표시·위쪽 정렬 | 현장에서 핸디로 출하 확정하는 방식과 같음, 잘못 누름 방지 |
| 자동 출차 | [출차]를 안 누르면 **상차완료한 업무일(도착 센터 기준)이 지나면 출차**. DB에 쓰지 않고 조회 때 판단(`departureOf`) | 버튼을 잊어도 다음 날 재개로 수량이 늘지 않게 |
| 출차 시각 표시 | PDA 완료 화면·목록 카드, 웹 ASN 상세·ASN·상차 현황(상태 아래), A4 상차확인서 | Sol 선택(전부) |

마이그레이션 `20261112000000_load_depart`: tb_load_h 출차 시각·처리자, 상차 이력 DEPART, ASN 이력 LOAD_DEPART, CHECK(출차는 상차완료일 때만).

| 시점 | 변경 |

| 품목 줄 | 검수자 2명 이상이면 "홍길동 40 BOX · 김민수 —" |
| 검수 확정 확인 창 | 차이 품목마다 수량·상태를 보고 **그 자리에서 사유 선택**, 빈 사유·사진 없으면 확정 버튼 막음 |
| 실물 없음(0 확인) | 사유 드롭다운·소비기한·로트 칸을 숨기고(사유는 서버가 "미도착" 자동), 품목명·수량은 품목코드와 같은 회색("0 확인" 글자는 제외) |

## 9. 결론

PDA 상차등록은 한 화면에서 날짜와 보기 버튼으로 모든 차량을 보게 됐고, 상차 재개는 **지시 상차·출차 전**으로 좁혀 **출차** 단계와 함께 정의서 v1.6에 담았다. 오전 작업분은 운영·시연 DB와 시연 사이트까지 반영했다. 입고검수 PDA도 같은 UI로 맞추고, 여러 검수자가 함께 셀 때는 차이 사유를 확정 때 한 번만 받도록 바꿨다. 입고검수 변경분은 커밋만 해 두었고, 병합·시연 반영과 대시보드 진행 막대 결정이 다음 순서다.
