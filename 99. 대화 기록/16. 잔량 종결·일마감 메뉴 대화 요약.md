# 잔량 종결·일마감 메뉴 대화 요약

## 1. 요약

**결론.** 웹 사이드바 '입고 운영' 그룹의 비어 있던 **"잔량 종결·일마감"** 메뉴(`/closing`)를 열고 **잔량 종결 탭**과 **일마감 탭**을 모두 만들었다. 잔량 종결은 DB 변경 없이(정의서 ERD에 이미 있던 종결 칼럼·이력·사유 코드 그룹) 만들었고, 일마감은 정의서 9장 ERD의 TB_DAILY_CLOSE를 새로 만들었다(시험 DB에만 적용).

**배경.** 15번 기록 8-2장에서 다음 개발 순서를 "잔량 종결 → 일마감 → 입고검수 실적 조회 → 입고취소 역전표"로 제안했고, Sol이 메뉴 생성을 지시했다. 시안(`02. IA/시안/approval-list.html`)과 사이드바 설정에 메뉴가 "잔량 종결·일마감" 하나로 되어 있어, 한 메뉴 안에 탭 두 개로 구성했다.

**대화 기록 원칙 (Sol 결정).** 메뉴를 새로 만들면 대화 기록도 기존 파일에 덧붙이지 않고 **번호를 올린 새 파일**로 남긴다. 파일은 지우지 않고 버전을 올려 새로 만든다는 원칙과 같다.

## 2. 잔량 종결 탭 (정의서 ⑦ · 4-2 · 5-1 · D17)

| 항목 | 내용 |
| --- | --- |
| 사용자 | 3PL 관리자·운영담당 (새 권한 `closing`). 화주사 계정은 메뉴가 보이지 않고 서버에서도 막는다 |
| 대상 | 미종결(승인·부분입고) 입고예정 전부 — 기간 조건 없이, 소속 센터 범위(센터 없는 계정은 전체) |
| 목록 열 | 고르기 · 입고예정번호(누르면 입고예정 조회 상세) · 화주사 · (센터) · 입고예정일 · 경과 · 상태 · 진행률 · 잔량(단위별 합계, 잔량 품목 수/전체) · 오는 중(ASN 대수) · 마지막 입고 · 종결 요청 메모 |
| 정렬 | 입고예정일이 오래된 건이 위 |
| 거르기 | 화주사 · 센터(여러 센터일 때) · 경과(전체/기준 초과) · 검색(입고예정번호·화주사·품목) |
| 경과 강조 | 운영 설정 '미종결 알림 기준 경과일' 이상이면 빨강, 화면 위 붉은 띠 + 탭의 ⚠ 숫자 (입고예정 조회와 같은 규칙) |
| 종결 | 고르기 → [잔량 종결 N건] → 사유 창(사유 필수 — 미도착·화주사 요청·기타(상세 필수), 대상 목록·잔량 표시) → 확정. **건별·일괄 모두 가능, 한 번에 최대 50건** |
| 처리 | 라인별 잔량(승인 − 입고 − 반송 − 종결)을 종결 수량으로 옮기고 상태를 **종결**로, 종결 사유·시각·처리자 저장, 처리 이력 "잔량 종결" |
| 일괄 처리 방식 | 고른 건 중 한 건이라도 막히면 **아무것도 바꾸지 않고** 어느 건이 왜 막혔는지 알려 준다 |
| 대시보드 연결 | 3PL 대시보드 "오래된 미종결 입고예정" 카드의 링크를 이 화면으로 바꿈 |

**임시안 (Sol 확인 필요).**

| 항목 | 임시안 | 이유 |
| --- | --- | --- |
| 오는 중인 차량 | 아직 입고되지 않은 ASN(등록·상차중·상차완료)에 담긴 입고예정은 **종결 불가**(고르기 칸 잠김). 검수 확정 뒤 종결하거나 화주사가 ASN을 취소한 뒤 종결 | 실물이 오는 중인데 잔량을 닫으면 도착 물량이 초과(3단계 배분)로 잡힌다 |
| 일괄 상한 | 한 번에 50건 | 잘못 눌러 대량 종결하는 일 방지 |
| 화주사 종결 요청 메모 | 목록에 표시만 한다. 화주사가 메모를 남기는 화면은 아직 없다 | 정의서 D17: 종결은 3PL만, 화주사는 메모만 |

## 3. 일마감 탭 (정의서 ⑦ · D18 · D21)

**일마감이 하는 일.** 센터의 **지금 업무일**을 마감한다(센터·업무일당 1회). ① 아직 일마감되지 않은 **검수 확정 실적을 확정**하고(실적에 이 일마감을 연결), ② **기한경과 승인 전 입고예정을 취소**한다. 전표를 닫지 않으므로 미종결 입고예정·승인 이후 건은 건드리지 않는다.

| 영역 | 내용 |
| --- | --- |
| ① 상태 | 센터 · 업무일 · [미마감/마감됨] · 업무일 시작 · 일마감 예정 시각 · 유예 기준. 센터가 여럿이면 고르기. **[일마감 실행]** (마감됐으면 비활성, 마감 시각·처리자·건수 표시) |
| ② 확정할 검수 실적 | 검수번호(웹 검수 결과로) · 업무일(이전 업무일이면 표시) · 확정 시각 · 차량 · 화주사 · 구분 · 품목 · 입고 · 반송 · 차이 · 확정자 |
| ③ 기한경과 취소 대상 | 입고예정번호(승인 대기 상세로) · 화주사 · 입고예정일 · 상태 · 취소 예정일. "살릴 건은 일마감 전에 승인" 안내 |
| ④ 미종결 입고예정 | 건수 · 경과 기준 초과 건수 + [잔량 종결 탭으로] — 일마감과 무관함을 안내 |
| ⑤ 일마감 이력 | 최근 14번: 업무일 · 마감 시각 · 처리자 · 확정 실적(대·품목) · 입고 · 반송 · 기한경과 취소 |
| 실행 확인 창 | 확정할 실적 건수·수량, 취소할 건수, "미종결은 그대로" — 되돌릴 수 없음 |
| 탭 표시 | 미마감이면 일마감 탭에 ⚠ 기한경과 취소 대상 수 |
| 대시보드 | 3PL 대시보드 일마감 카드의 [일마감 화면 (준비 중)]을 실제 링크로 바꿈 |

**처리.** 실행 순간의 대상을 다시 계산해 화면에서 본 대상(실적·취소 건)과 다르면 아무것도 하지 않고 다시 확인하게 한다. 같은 센터 일마감이 동시에 돌지 않게 센터를 잠근다. 기한경과 취소는 사유 X04 "기한경과(일마감 자동)", 처리자 "이름 (일마감)", 이력 "기한경과 취소"로 남긴다.

**DB.** `tb_daily_close`(센터·업무일 유일, 마감 시각·처리자, 확정 실적 수·품목 수, 입고·반송 수량 합계(기준 단위), 기한경과 취소 수) + `tb_rcv_h.daily_close_id`. 마이그레이션 `20261112010000_daily_close` — **시험 DB에만 적용**, 운영·시연 DB는 병합 때 함께 적용한다.

**임시안 (Sol 확인 필요).**

| 항목 | 임시안 | 이유 |
| --- | --- | --- |
| 마감할 날 | 센터의 **지금 업무일만** 마감한다. 지난 업무일을 따로 골라 마감하지 않는다 | 화면·규칙 단순화. 건너뛴 날의 실적은 다음 마감에 함께 확정된다(아래) |
| 확정 대상 실적 | 아직 일마감되지 않은 검수 확정 실적 **전부**. 지난 업무일에 마감을 건너뛴 건과 **마감 뒤 같은 업무일에 확정된 건**은 다음 일마감 때 확정된다. 귀속 업무일은 확정 시각 기준 그대로(D21) | 실적이 빠지지 않게. 이전 업무일 건은 표에 "이전 업무일"로 표시 |
| 되돌리기 | 일마감 취소 없음 | 확정 실적·기한경과 취소는 되돌리지 않는 원칙(정의서 핵심 원칙 2) |
| 일마감 시각 | 센터의 "일마감 예정 시각"은 안내용이다. 그 시각 전에도 실행할 수 있고, 자동 실행은 없다 | 정의서: "매일 3PL이 실행" |

**점검 (시험 DB).** 일마감 9건 통과 — 화주사 계정 막음, 화면에서 본 대상과 다르면 막음, 업무일 다르면 막음, 막힌 뒤 그대로, 실행 성공(마감 기록·건수·처리자), 기한경과 건 취소(사유 X04·이력), 같은 업무일 두 번 막음, 화면 마감됨 표시. 실행 후 시험 데이터는 원래대로 되돌렸다(마감 기록 삭제, 취소한 입고예정 복구). **시험 DB에 확정된 검수 실적이 없어 "실적 확정(연결)" 부분은 실제 데이터로 돌려 보지 못했다**(코드상 처리). X04 사유는 운영·시연·시험 DB 모두 있음. 단위 시험 74건, 빌드 통과.

## 4. 점검 (잔량 종결)

| 점검 | 결과 |
| --- | --- |
| 단위 시험 | 74건 통과 (잔량 종결 규칙 3건 추가 — 잔량 계산, 가능 조건, 막는 조건) |
| 서버 처리 (시험 DB) | **12건 통과** — 오는 중 ASN이면 막음·막힌 뒤 그대로, 화주사 계정 막음, version 불일치 막음, 사유 없으면 막음, 종결 성공(상태·version·종결 수량·사유·시각·처리자·이력), 이미 종결된 건 막음. 성공 경로는 시험 DB에 임시 입고예정을 만들어 확인한 뒤 지웠다(기존 데이터 그대로) |
| 목록 조회 (시험 DB, 읽기 전용) | 3PL 계정 미종결 2건(둘 다 오는 중 ASN 있음 → 고를 수 없음), 화주사 계정 0건 |
| 사유 코드 | 운영·시연·시험 DB 모두 REMAIN_CLOSE(미도착·화주사 요청·기타) 있음 |
| 빌드 | `next build --webpack` 통과 |

화면은 시험 DB의 미종결 2건이 모두 오는 중 ASN이 있어, 실제로 골라서 종결하는 화면 동작은 Sol 확인이 필요하다.

## 5. 남은 일

- 잔량 종결·일마감 화면 확인 (Sol) → 잔량 종결 임시안 3가지, 일마감 임시안 4가지 확인
- 검수 확정 실적이 있는 상태에서 일마감 실적 확정 확인
- 입고예정 조회 상세에서 건별 [잔량 종결] 버튼을 둘지 (지금은 이 화면에서 한 건만 골라 종결)
- 커밋·병합·시연 반영은 Sol 확인 후 — **운영·시연 DB에 `20261112010000_daily_close` 적용 필요**

## 6. 결론

"잔량 종결·일마감" 메뉴를 열고 두 탭을 만들었다. 잔량 종결은 미종결 입고예정을 경과일 순으로 보고 건별·일괄로 사유와 함께 종결하며, 오는 중인 차량이 있는 건은 임시로 막았다. 일마감은 센터의 지금 업무일에 아직 마감되지 않은 검수 실적을 확정하고 기한경과 승인 전 건을 취소하며, 되돌리기는 없다. 서버 점검 21건(종결 12·일마감 9)과 단위 시험을 통과했고, 일마감 테이블은 아직 시험 DB에만 있다.
