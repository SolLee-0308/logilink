# 입고검수 실적 메뉴 대화 요약

## 1. 요약

**결론.** 웹 사이드바 '입고 운영' 그룹의 비어 있던 **"입고검수 실적"** 메뉴(`/rcv-results`)를 열었다. 3PL이 PDA로 한 입고검수를 **차량(검수 1건) 단위로 조회**하는 화면이다. 조회 전용이고 DB 변경은 없다.

**배경.** 15번 기록 8-2장의 개발 순서(잔량 종결 → 일마감 → **입고검수 실적 조회** → 입고취소 역전표)대로 진행했다. 일마감 탭의 "확정할 검수 실적" 목록을 기간 조회로 넓힌 화면이다. Sol은 잔량 종결·일마감과 이 화면을 **한꺼번에 검수**하기로 했다.

## 2. 화면

| 항목 | 내용 |
| --- | --- |
| 사용자 | 3PL 관리자·운영담당 (새 권한 `rcvResults`, 조회 전용). 소속 센터 범위(센터 없는 계정은 전체). 화주사는 기존처럼 ASN 상세의 검수 결과로 본다 |
| 탭 | **확정**(기본) / **검수 중** |
| 기간 | **업무일**(D21) — 확정 탭은 검수 확정 시각, 검수 중 탭은 시작 시각이 속한 센터 업무일. 처음에는 최근 7일(오늘 포함), 빠른 선택 오늘·최근 7일·직접 |
| 거르기 | 화주사 · 센터(여러 센터일 때) · 일마감(전체/미마감/마감됨) · 차이(전체/차이 있음) · 검색(검수번호·차량·상차확인서·ASN·품목) |
| 열 (확정) | 검수번호 · 업무일 · 확정 시각 · 차량 · 화주사 · (센터) · 상차(지시/무지시, 상차확인서·ASN 번호) · 품목 · 입고 · 반송 · 차이 · **일마감**(마감한 업무일 / 미마감) · 확정자 |
| 열 (검수 중) | … 시작 시각 · 품목 · 입고 · 반송 · 검수자 수 |
| 합계 줄 | 거른 목록의 입고·반송 합계(기준 단위), 차이 있음 대수, 미마감 대수 |
| 상세 | 검수번호를 누르면 지시 상차는 **ASN·상차 현황 상세**, 무지시 상차는 **상차 상세**의 검수 결과 카드(품목별 입고·반송·사유·사진·자동 배분)로 간다 — 새 상세 화면을 만들지 않고 기존 화면을 쓴다 |

수량은 품목마다 단위가 달라 **기준 단위 합계**로 보여 준다(입고 = 정상, 반송 = 훼손 + 품목 불일치).

## 3. 점검

| 점검 | 결과 |
| --- | --- |
| 조회 (시험 DB, 읽기 전용) | 검수 중 1건(RC-20261112-0001, 업무일 11-12, 입고 74·반송 5, 링크 ASN·상차 현황 상세) 조회됨. 기간 최근 7일·전체·오늘 모두 같은 결과. 화주사 계정 0건 |
| 확정 탭 | 시험 DB에 확정된 검수가 없어 빈 목록 — **확정 실적이 있는 상태의 화면은 Sol 검수 때 확인 필요** |
| 단위 시험·빌드 | 74건 통과, `next build --webpack` 통과 |

## 4. 남은 일

- Sol 한꺼번에 검수: 잔량 종결·일마감(16번) + 입고검수 실적(이 기록)
- 시험 DB에 검수 확정 실적을 만든 뒤 확정 탭·일마감 실적 확정을 함께 확인
- 다음 메뉴 후보: **입고취소 역전표**(확정 실적을 되돌림, 정의서 ⑥ "적치 시작 전까지만") — 이 화면이나 검수 결과 상세에 [입고취소]를 둘 자리
- 커밋·병합·시연 반영은 검수 후 (16번의 일마감 마이그레이션 함께)

## 5. 결론

입고검수 실적 메뉴를 열어 3PL이 검수 확정·검수 중 실적을 업무일 기준으로 조회하고, 일마감 여부와 차이를 바로 볼 수 있게 했다. 상세는 기존 ASN·상차 현황/상차 상세의 검수 결과를 쓴다. DB 변경은 없고, 확정 실적이 있는 화면은 Sol 검수 때 함께 확인한다.
