# 입고취소 역전표 대화 요약

## 1. 요약

**결론.** 잘못 확정한 검수 실적을 3PL 관리자가 **입고취소**하면, 확정 기록은 그대로 두고 **역전표(RV-…)**를 만들어 자동 배분을 되돌린다. 입고예정의 입고·반송 누계와 상태, ASN 상태가 되돌아가고, 같은 차량을 PDA에서 **다시 검수**할 수 있다. 입고검수 실적 화면(17번)에 [입고취소] 버튼과 **입고취소 탭**을 붙였다.

**배경.** 15번 기록 8-2장의 개발 순서 마지막 항목이다. 정의서 ⑥에 "입고취소 역전표 후 재검수 (적치 시작 전까지만)"이 있으나 적치 모듈이 아직 없어 가능 기간을 정해야 했다.

## 2. 일반 물류센터 기준 (Sol 질문에 대한 검토)

| 항목 | 일반적인 방식 |
| --- | --- |
| 기능 자체 | 대부분의 WMS·ERP에 있는 **예외 처리 기능**(입고 역처리). 매일 쓰는 기능은 아님 |
| 방식 | 확정 기록을 고치거나 지우지 않고 **반대 전표(역전표)**를 만든다 — 정의서 핵심 원칙 2와 같음 |
| 쓰는 상황 | 다른 화주사·차량으로 잘못 확정, 수량 오입력, 반송할 물량을 정상으로 받음 |
| 제한 | 적치 전 또는 **당일 마감 전**까지만, 관리자급, 사유 필수, 되돌린 뒤 재검수. 그 뒤에는 재고 조정·반품 출고 등 다른 전표로 |

## 3. 결정 (Sol 확인)

| 항목 | 결정 |
| --- | --- |
| 가능 기간 | **지금은 일마감 전 확정 실적만.** 적치 모듈을 만들 때 **"적치 시작 전"을 함께** 건다(두 조건 모두 지킴). 정의서의 "적치 시작 전까지만"은 그때까지 일마감으로 대신한다 — 임시안 |
| 이유 | 일마감 = 실적 확정이라 마감 뒤 실적이 바뀌면 집계가 어긋난다. 현장의 "당일 마감 전까지"와 같다 |
| 확장 방법 | 가능 여부를 규칙 파일 한 곳(`src/domain/rcv-cancel-rules.ts`)에 모으고 `putawayStarted` 자리를 미리 두었다 |

## 4. 구현

| 항목 | 내용 |
| --- | --- |
| 누가 | **3PL 관리자만** (`rcvResults` edit). 운영담당은 조회만 |
| 어디서 | 입고검수 실적 › 확정 탭 줄 끝 [입고취소] (못 하는 줄은 "–", 마우스를 올리면 이유) |
| 사유 | 필수 — 공통코드 `RCV_CANCEL` 임시안: 수량 오입력 · 품목 오입력 · 화주사·차량 오선택 · 기타(상세 필수) |
| 막는 경우 | 확정 아님, **일마감됨**, 배분된 입고예정이 그사이 **종결·취소**됨, version 바뀜, 사유 없음 |
| 처리 | ① 역전표 `tb_rcv_reverse`(RV-YYYYMMDD-NNNN, 검수 1건당 1장, 되돌린 입고·반송 수량, 사유, 처리자) ② 원래 배분은 지우지 않고 **되돌림 표시 + 역전표 연결**(합계에서 빠짐) ③ 입고예정 라인 입고·반송 누계를 빼고 상태 재계산(처리 0 → 승인, 잔량 남음 → 부분입고, 잔량 0 → 입고완료) + 이력 "입고취소" ④ ASN 입고완료 → 상차완료, 상차지시서 검수완료 → 상차완료 + ASN 이력 "입고취소 (역전표)" ⑤ 검수 상태 **입고취소** — 같은 차량을 다시 검수할 수 있다 |
| 입고취소 탭 | 입고검수 실적에 세 번째 탭. 역전표 번호·처리자·사유와 원래 수량을 보여 준다(기간 = 역전표 시각의 업무일) |
| 문구 | PDA 검수 완료 화면·확정 후 입력 막힘 안내의 "입고취소는 추후 제공"을 "3PL 관리자가 일마감 전에 입고취소한 뒤 다시 검수"로 바꿈 |
| DB | 마이그레이션 `20261112020000_rcv_reverse` — 검수 상태 CANCELED, 입고예정·ASN 이력 행위 RECEIVE_CANCEL, `tb_rcv_reverse`, `tb_rcv_alloc.reverse_id` + CHECK(되돌림 = 역전표 있음), 사유 코드 RCV_CANCEL. **시험 DB에만 적용** |

배분을 읽는 모든 조회(입고예정 조회 상세·차량별, ASN 분배 잔량, 검수 결과, 잔량 종결)는 이미 `되돌림 아님`만 세고 있어 따로 고치지 않았다. 진행·확정 검수를 차량 실적당 1건으로 막는 부분 유일 인덱스도 입고취소 상태를 제외하므로 재검수가 바로 된다.

## 5. 점검

| 점검 | 결과 |
| --- | --- |
| 단위 시험 | 77건 통과 (입고취소 규칙 3건 추가) |
| 서버 처리 (시험 DB) | **14건 통과** — 실적 목록에서 가능 표시, 운영담당 막음, version 다르면 막음, 사유 없으면 막음, 일마감된 실적 막음, 입고취소 성공(상태·version·역전표 번호·수량·처리자·배분 되돌림·입고예정 누계 6 → 0·부분입고 → 승인·이력), 두 번 입고취소 막음, 입고취소 탭에 보임, **같은 차량 다시 검수 시작 가능**. 시험 DB에 확정 검수가 없어 임시 데이터(무지시 상차·확정 검수·임시 입고예정)를 만들어 점검하고 지웠다 |
| 지시 상차(ASN) 경로 | ASN 입고완료 → 상차완료 되돌림은 코드상 처리, 임시 데이터가 무지시라 실제로 돌리지 못했다 — Sol 검수 때 확인 |
| 사유 코드·RLS | 시험 DB에 RCV_CANCEL 4개, `tb_rcv_reverse` RLS 켜짐 |
| 빌드 | 통과 |

## 6. 남은 일

- Sol 일괄 검수: 16번(잔량 종결·일마감) + 17번(입고검수 실적) + 18번(입고취소)
- 임시안 확인: 가능 기간(일마감 전), 관리자만, 사유 코드 목록
- ASN 상세의 검수 결과 카드는 입고취소된 검수를 보여 주지 않는다(진행·확정 검수만). 역전표 이력은 ASN 처리 이력에 남는다 — 상세에도 "입고취소된 검수" 줄을 둘지 검수 때 결정
- 적치 모듈을 만들 때 `rcv-cancel-rules.ts`에 "적치 시작 전" 조건 추가
- 커밋·병합·시연 반영(마이그레이션 2개: daily_close, rcv_reverse)

## 7. 결론

입고취소는 확정 기록을 고치지 않고 역전표로 배분을 되돌리는 방식으로 만들었다. 지금은 3PL 관리자가 일마감 전 실적만 취소할 수 있고, 적치 모듈이 생기면 "적치 시작 전" 조건을 더한다. 되돌린 뒤에는 같은 차량을 다시 검수할 수 있으며, 서버 점검 14건과 단위 시험을 통과했다.
