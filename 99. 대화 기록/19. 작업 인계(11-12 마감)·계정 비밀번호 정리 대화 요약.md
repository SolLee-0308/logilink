# 작업 인계(11-12 마감)·계정 비밀번호 정리 대화 요약

## 1. 요약

**결론.** 11-12에 만든 메뉴 3개(잔량 종결·일마감, 입고검수 실적, 입고취소 역전표)는 **모두 미커밋**이며 Sol이 **한꺼번에 검수**하기로 했다. 마이그레이션 2개(`20261112010000_daily_close`, `20261112020000_rcv_reverse`)는 **시험 DB에만** 적용되어 있다. 시험 DB(3001)의 모든 계정은 `.env`의 마스터 비밀번호로 맞췄다. 새 대화에서는 **3장 일괄 검수 → 4장 반영 절차** 순서로 이어 가면 된다.

**대화 기록 원칙.** 새 메뉴마다 번호를 올린 새 파일로 남긴다(16번부터). 파일은 지우지 않고, 바꿀 때는 버전을 올린 새 파일로 만든다.

## 4. 반영 절차 (검수 후)

1. 브랜치를 만들어 미커밋 작업 커밋(2장 표, 제외 목록 지킴) → `next build --webpack` 확인 → main 병합(--no-ff)·push
2. **운영 DB**에 `20261112010000_daily_close` → `20261112020000_rcv_reverse` 순서로 적용, 읽기 전용 확인(테이블·RLS·사유 코드 REMAIN_CLOSE·RCV_CANCEL·X04)
3. **시연 DB**에도 같은 2개 적용 (`.env.demo`, 시연 프로젝트 ref 확인 안전장치)
4. deploy 브랜치 갱신: `git commit-tree "$(git rev-parse 'main:03. 개발')" -p deploy -m …` → `git branch -f deploy` → push → 시연 사이트 반영 확인(빌드 식별값이 바뀌는지, 약 70초)

순서를 바꾸면(코드 먼저) 새 칸이 없는 DB에서 오류가 난다.

비밀번호 값은 대화·기록·메모 어디에도 남기지 않았다. 선생님께 알렸던 예전 시연 전용 비밀번호는 시연 DB에서 더 이상 쓰이지 않는다.

**교훈 (메모에 저장).** 비밀번호 일괄 변경은 ① 대상 DB를 먼저 확인하고 ② 바꾸기 전 해시를 백업하고 ③ 바꾼 뒤 그 값으로 로그인되는지 확인한다. `.env` 값이 바뀌면 이미 바꾼 계정과 어긋날 수 있다.
