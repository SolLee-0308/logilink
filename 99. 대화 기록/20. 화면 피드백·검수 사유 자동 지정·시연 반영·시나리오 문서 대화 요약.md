# 화면 피드백·검수 사유 자동 지정·시연 반영·시나리오 문서 대화 요약

## 1. 요약

**결론.** 화면 피드백 6건을 반영하고, 입고검수의 차이·반송 사유를 **검수자가 고르지 않고 수량으로 시스템이 정하도록** 바꿨다(정의서 v1.7). 11-12 일괄 검수분(잔량 종결·일마감, 입고검수 실적, 입고취소 역전표)과 함께 **main 병합 → 운영·시연 DB 마이그레이션 → 시연 배포**까지 마쳤다. 시연 DB는 시험 DB(3001) 데이터로 통째 교체했고, 시연 링크에서는 **대시보드를 "준비 중입니다."로 막았다.** 처음 쓰는 사람용 **시연 시나리오 문서**를 새로 썼다.

**배경.** 시험 서버(3001)에서 Sol이 화면을 검수하며 피드백을 주었고, 이후 선생님·외부 시연자가 시연 링크만 보고 테스트할 수 있게 정리할 필요가 있었다.

## 3. 입고검수 차이 사유 자동 지정 (정의서 v1.7)

**Sol 질문.** 수량 초과·부족은 사용자가 드롭다운에서 고르지 않고 시스템이 해야 하지 않나?

**검토.** 입고검수 사유 목록(RCV_DIFF)의 "수량 부족·수량 초과"는 원인이 아니라 **차이의 종류**라서, 수량으로 이미 정해지는 값을 다시 고르는 이중 입력이었다. 서버는 사유가 수량과 맞는지 검사하지 않아 **부족인데 "수량 초과"를 골라도 저장**되는 정합성 문제가 있었다. 상차 차이 사유는 원인(재고 부족·적재 공간 부족 등)을 고르는 것이라 그대로 둔다.

| 선택지 | 데이터 정확성 | 결론 |
| --- | --- | --- |
| 기존 유지 | 수량과 반대인 사유도 저장됨 | 권하지 않음 |
| A. 완전 자동 | 정확 | **채택 (Sol 확정)** |
| B. 자동 + 변경 가능 | 바꾸면 어긋날 수 있음 | 처음 권했으나 A로 수정 |

**구현.**

| 항목 | 내용 |
| --- | --- |
| 규칙 | `src/domain/rcv-rules.ts` `autoReason` — 라인당 1개: 품목 불일치(V04) > 미도착·0 확인(V05) > 훼손·오염 반송(V03) > 수량 부족(V01) > 수량 초과(V02) |
| 서버 | 검수 확정 때 항상 수량으로 사유를 다시 기록, 차이가 없어진 라인의 사유는 지움. `setRcvLineInfo`는 소비기한·로트만 받음(사유 변경 경로 차단). 공통코드가 꺼져 있으면 확정 막고 관리자 안내 |
| PDA | 품목 줄·확정 창의 사유 드롭다운 삭제 → "사유: 수량 부족 (자동)" 표시만. 확정을 막는 조건은 훼손 사진 누락만 |
| 정의서 | `01. 프로세스/06-입고 업무프로세스 정의서_v1.7.md` 새 파일(v1.6은 그대로) — ⑥·C7·D19 수정, **D24 추가** |
| 시험 | 단위 시험 78건 통과(자동 사유 시험 추가). `scripts/check-rcv-rules.ts`는 새 규칙에 맞게 고쳤으나 실행 후 시드 재투입이 필요해 **실행하지 않음** |
| 적용 범위 | 입고검수 PDA만. 상차 차이 사유, 반려·취소·잔량 종결·역전표·상차 재개 사유는 그대로. 기존 확정 건은 건드리지 않음 |

## 8. 남은 일·주의

- 이 기록(20번)은 아직 커밋하지 않음.
- `scripts/check-rcv-rules.ts` 통합 점검은 시드 재투입이 필요해 미실행 — 필요할 때 Sol 확인 후 실행.
- 대시보드 개발(진행 막대 A/B 등)은 모든 메뉴 개발 후 — 끝나면 `dashboardReady` 되돌리기.
- PDA 대시보드 탭 글자를 "준비 중"으로 바꿈 — "대시보드" 유지 여부 Sol 확인 대기.
- 시연 시나리오 문서에 비밀번호를 넣을지 Sol 결정 대기.
- 세션 임시 폴더의 백업(시연 계정 해시, 이전 시연 데이터)은 세션이 끝나면 없어질 수 있음.
