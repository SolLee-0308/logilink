# 입고 대기·출차 시스템 처리·입차 신설·정의서 v1.8 초안 대화 요약

## 1. 요약

입고예정 조회의 **'오는 중'이 운송 중인 차량을 뜻하는지** 묻는 질문에서 시작했다. 확인해 보니 '오는 중'은 정의서에 없는 용어였고, 실제로는 **검수 확정 전인 모든 ASN(등록·상차중·상차완료)의 수량**이었다. 아직 출발하지 않은 차량과 이미 도착한 차량까지 들어 있었다. 여기서 출발해 출차 확정 방식, 입차 기록, 검수 시작 시점을 일반 물류센터 관행에 맞춰 다시 정했고, **정의서 v1.8 초안**(`01. 프로세스/07-입고 업무프로세스 정의서_v1.8.md`)을 작성했다. **코드 작업은 아직 시작하지 않았다.**

**다음 시작 시 할 일: Sol이 정의서 v1.8 초안을 검토한다(2026-11-14 예정).** 검토가 끝나면 아래 6장 순서대로 작업한다.

## 4. 논의 흐름

1. **'오는 중'의 뜻**: 운송 중이 아니라 "ASN에 배정됐지만 입고되지 않은 수량". 상차 전 차량과 도착 후 검수를 기다리는 차량까지 포함한다.
2. **개선안 A/B/C**: A 이름만 변경 / **B 이름 변경 + 단계 표시(권장)** / C 센터 도착 기록 신설.
3. **자동 출차의 위험**: 실제로는 출발 전인데 출차로 보임, 실제로는 출발했는데 출차 대기로 보임, 실제가 아닌 출차 시각 표시, 업무일 경계에서 재개 가능 시간이 거의 없음, 기준이 도착 센터의 업무일, 설정을 바꾸면 소급 변경되고 이력이 없음, 집계 누락.
4. **일반 물류센터 관행**: 출하 확정과 입차는 사람이 실제 시점에 기록한다. 시스템이 대신 처리할 때는 마감 배치로 처리하고 '시스템 처리'로 저장·이력을 남긴다. 일반적인 ASN은 출하 확정 때 발송하지만, 우리 ASN은 상차 지시를 겸해 상차 전에 등록되므로 "ASN 있음 = 오는 중"이 성립하지 않는다.
5. **수동 일마감**: 일반적인 방식이고, 쉬는 날에는 건너뛰는 것이 정상이다. 다음 일마감이 밀린 대상을 함께 처리하게 하면 건너뛰어도 문제가 없다.
6. **입차 방식**: 경비실 입력, 차량번호 인식(LPR), 기사 셀프 체크인, 입고 담당 PDA 중 **3PL 입고검수자 PDA 스캔**을 택했다.
7. **검수 시작 시점 분리**: ① 두 번 스캔 / **② 스캔 = 입차, 첫 입력 = 검수 시작(확정)**. 새 메뉴 없이 기존 입고검수 메뉴 안에 둔다.

## 5. 확정 사항 (2026-11-13 Sol)

| 번호 | 결정 |
|---|---|
| 1 | 검수 시작 시점 분리: 상차확인서·상차지시서 스캔(또는 차량번호) = **입차**, 첫 입력(품목 스캔 또는 0 입력) = **검수 시작** |
| 2 | **자동 출차 폐지**. 사람이 실제로 떠나는 시점에 [출차]로 확정 |
| 3 | 누락된 출차는 **일마감 때 '일마감 처리'로 저장**하고 이력 기록. 대상 = 출차·입차 기록 없음 + **일마감하는 업무일 전날까지 상차완료**. 시각 = 일마감 실행 시각, 처리자 = 일마감한 담당자. 일마감 화면에 미리 보여 주고 실행 |
| 4 | 입차할 때 출차가 없으면 **'입차 처리'로 출차 저장**(시각 = 입차 시각) |
| 5 | 입차 없이 품목을 입력해도 막지 않음(스캔 = 입차이므로 사실상 항상 기록됨) |
| 6 | '오는 중' → **'입고 대기'**, 6단계: 상차 전·상차중·출차 대기·운송 중·도착·검수 대기·검수중 |
| 7 | 입차는 새 메뉴 없이 **기존 PDA 입고검수 메뉴** 안에 둠 |
| 8 | 정의서 **v1.8 새 파일** 하나에 모두 반영 |
| 구현 ① | **(나)** 입고검수 전표는 지금처럼 **상차확인서·상차지시서 스캔 때 생성**하고, 검수 시작 시각을 따로 기록 |
| 구현 ② | 입차 취소 시 입고검수 전표도 함께 취소(첫 입력 전만, 사유 필수, 출차는 유지) |
