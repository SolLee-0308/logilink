# 정의서 v1.9 확정·입차 개발·화면 검수 피드백 대화 요약

## 1. 요약

Sol이 정의서 v1.8 초안을 검토해 **v1.9로 확정**했다(`01. 프로세스/08-입고 업무프로세스 정의서_v1.9.md`). 새 브랜치 `feat/1114-arrival`에서 v1.9 기준 개발을 끝내고 **c52fd5e로 커밋**했다(main 병합·push 전). 이후 Sol이 웹·PDA 화면을 검수하며 정렬·조회조건·알림·PDA 스캔 영역 등 피드백을 다수 냈고, 모두 반영했으나 **이 부분은 아직 커밋하지 않았다.**

**다음 시작 시 할 일:** Sol이 남은 화면 검수를 이어 간다 → 피드백 반영 → 커밋 → main 병합 → 운영·시연 DB 마이그레이션(20261114 3개) → 시연 반영.

## 2. 시작 전 환경

- 시험 DB: `npx prisma dev --name logilink-test --detach`(03. 개발), `localhost:51214`
- 시험 서버: `npm run dev:test` → http://localhost:3001
- 데이터를 바꾸는 점검은 별도 점검 DB에서: `npx prisma dev --name logilink-check --detach`(51230) 후 시드 → `scripts/check-arrival-rules.ts`(32/32). 시험 DB 시드는 Sol 데이터를 지우므로 하지 않는다.

## 5. 화면 검수 피드백 반영 (미커밋)

### 5-1. 공통 규칙

| 항목 | 결정 |
| --- | --- |
| 고정 영역 | 제목·조회조건·탭은 위치가 바뀌지 않게. 처리 결과·오류는 화면 위 가운데 토스트, 계속 볼 상태 알림은 탭 아래·목록 바로 위 |
| 조회조건 | 줄바꿈되면 같은 순번 칸끼리 입력칸 시작점을 맞춤(표처럼), 항목명은 왼쪽 정렬 |
| 그리드 정렬 | 열 제목은 항상 가운데. 데이터는 자릿수가 같은 값(번호·날짜·코드·차량)과 상태 배지는 가운데, 길이가 다른 글은 왼쪽, 수량은 오른쪽. 예외는 Sol이 화면별로 지정 |
| 일시 표기 | 1줄 YYYY-MM-DD, 2줄 이름(왼쪽)·시각(오른쪽). 공통 부품 `DateStamp` |
| 기타 | 열 제목 고정, 총 건수는 상태 탭 줄 오른쪽 끝, 안내 박스 버튼은 같은 줄 오른쪽, 숫자 쉼표, "줄·종" → "품목", #·단위 열은 좁게·가운데, 소비기한·로트 열 분리, 왼쪽 메뉴 성 글자 원 로고 삭제 |

### 5-2. 화면별

| 화면 | 반영 |
| --- | --- |
| 입고예정 등록 | 소비기한·로트 경고를 입력칸 위쪽 테두리에 짧게 표시 |
| 입고예정 조회 | [상세] 버튼 삭제, 승인 열을 날짜/승인자·시각 형식으로 |
| 승인 대기 | 품목·수량 왼쪽, 상세 품목표 정리 |
| ASN 상세 | 입고검수·상차 실적 영역을 왼쪽(상태·번호·작업자)·오른쪽(시각)으로 배치, 검수 시작 = 첫 입력 시각 |
| ASN·상차 현황 | 서버에서 출고일 기간으로 조회(기본 오늘 ±3일), 오늘·내일·출고일 지난 요약은 기간과 무관 |
| 입고검수 실적 | 검수 중 탭은 기간과 상관없이 전부, 기간 이름(확정 업무일·입고취소 업무일), [오늘][최근 7일] 버튼, 화주사 찾기, 조건을 주소에 유지. 탭별 조건 변화는 그대로(Sol 결정) |
| 기준정보 | 품목 관리는 화주사를 먼저 골라야 품목을 읽음, 사용 여부 기본 "사용", 사유 코드 그룹은 드롭다운 + 상세 패널 위 그룹 안내(코드를 고르면 한 줄로 접힘) |
| PDA 상차 | 스캔 영역: 아이콘 삭제·품목코드+품목명, 지시·합계·남은 수량(부족 −, 초과 +), 수량 줄 배경 #FBFAFF, 입력칸 안내 글, 일치 품목은 목록 맨 아래 |
| PDA 입고검수 | 상차와 같은 스캔 영역(상차·정상·반송·남은 수량), 타임라인 삭제 후 상태 줄에 입차 시각, 반송은 별도 줄 붉은색, 일치·0 확인 품목은 맨 아래 |
