**① 품목 목록 엑셀 다운로드 (U58)**

품목 관리(3PL)·품목 조회(화주사) 목록 위 [엑셀 다운로드]. 범위는 화주사 = 자기 품목, 3PL = 고른 화주사의 품목이며, 화면 조회조건에 걸린 품목만 받는다. 내려받기 전용(다시 올리기 없음). 열은 품목코드 · 화주사 품목코드 · 품목명 · 온도대 · 기준단위 · BOX·PLT 입수 · 단위별 바코드 · 별칭 · 사용여부.

## 1. 요약

품목 화면에 **엑셀 다운로드**를 추가했고(U58), 입고예정 등록의 **AI 판독 탭을 엑셀 업로드 탭과 같은 단계 카드**로 바꿨다. 판독·엑셀 결과 편집 화면은 **빨강(확인 필요) / 노랑(입력 필요)** 두 가지 줄 색으로 정리하고, '원본과 대조함' 체크박스를 없앴으며, 중복 줄에 **[한 줄로 합치기]**를 넣었다(U59). 외부 API는 **Claude API(AI 판독)**와 **공공데이터 특일 정보(공휴일)** 두 개 모두 키를 넣고 동작을 확인했다. 정의서 v1.9 기준 **업무프로세스 도식화 프롬프트** 문서도 만들었다.

**모든 변경은 `feat/1114-arrival` 브랜치에 있으며 아직 커밋하지 않았다.** (마지막 커밋 86bcfc6)

**다음 시작 시 할 일:** Sol이 3001에서 화면 확인(품목 다운로드 버튼·AI 판독 탭·줄 색·합치기) → 커밋할 브랜치 결정 후 커밋 → 기준정보 › 휴무일에서 2026·2027 공휴일 불러오기 → 알림·이미지 저장소 외부 서비스 사용 여부 결정.

## 4. 입고예정 등록 — AI 판독 탭·편집 화면 (U59)

### 4-1. AI 판독 탭을 엑셀 업로드 탭과 같은 모양으로

| 항목 | 내용 |
| --- | --- |
| 카드 | 엑셀 탭과 같은 단계 카드(`ItemBulkScreen`의 Step) — 번호 상태 색 |
| 단계 | 2단계: ① 이미지 올리기 → ② 편집 화면에서 확인 후 저장. AI 판독은 양식이 없어 양식 단계는 두지 않음 |
| 이미지 올린 뒤 | 영역이 연보라로 바뀌고 '이미지 n장 / 최대 3장', 3장 미만이면 '[이미지 추가]', 3장이면 '아래에서 이미지를 빼세요' |
| 판독 버튼 | 엑셀 [파일 확인]처럼 1단계 카드 아래 [이미지 N장 판독] |
| 공통 영역 | `DropZone`에 고른 뒤 안내 문구 설정(`moreText`·`moreLabel`) 추가 — 엑셀 탭 문구는 그대로 |

### 4-2. 편집 화면 정리 (Sol 화면 피드백)

| 피드백 | 반영 |
| --- | --- |
| '확인 필요 n줄' 연한 주황 안내 상자 | 삭제 |
| '수량은 1 이상이어야 합니다'를 아래 줄 대신 칸에 | 소비기한·로트 '필수 입력'처럼 수량 칸 위쪽 테두리에 **'수량 입력'** |
| 품목 칸과 다른 칸의 입력 시작점 | 원본 글 줄 높이를 고정(22px + 6px)하고 원본 글이 있는 줄의 다른 칸·번호를 같은 만큼 내림 |
| 품목 미매칭 | 품목 칸 안에 빨간 글씨 **'품목을 매칭하세요.'**, 줄은 빨강, 아래 줄에는 띄우지 않음 |
| '단위를 고르세요.' | 품목을 못 찾은 줄에서는 생략(품목을 골라야 단위를 고를 수 있으므로) |

### 4-3. 줄 색 기준 (Sol 결정)

| 색 | 뜻 | 해당 |
| --- | --- | --- |
| 빨강(확인 필요) | 값은 있지만 틀렸을 수 있음 | 품목 미매칭 · 판독 신뢰도 0.8 미만 수량 · 품목에 없는 단위 · 하한보다 이른 소비기한 · 중복 줄 · 서버 오류 |
| 노랑(입력 필요) | 값이 비어 있음 | 단위·수량 없음 · 필수 소비기한·로트 없음 |

- 둘 다면 빨강. **빨강이 1줄이라도 있으면 저장 불가**(노랑도 필수값이라 저장 불가).
- 줄 위 태그: 빨강 [확인 필요] / 노랑 [입력 필요]. 보기 버튼 '확인 필요 n' → **'고칠 줄 n'**, 합계 줄 '확인 필요 n줄 · 입력 필요 n줄', 저장 실패 안내도 나눠 표시.

### 4-4. '원본과 대조함' 체크박스 삭제

- 기능 설명: AI가 신뢰도 0.8 미만으로 읽은 수량을 사람이 원본과 대조했다고 확인하는 칸이었고, 체크 전에는 저장이 막혔다(U27).
- 결정: 체크박스를 없애고 **수량 칸을 고치면(지우고 같은 값을 다시 입력해도) 확인한 것으로 보고 빨강 해제.** 줄 아래 안내 '원본 이미지와 대조해 수량을 다시 입력하세요'.
- 이 검사는 기존처럼 화면에서만 한다(서버 미검사 — 필요하면 추가).

### 4-5. 중복 줄 (Sol 질문: 같은 품목인데 로트·소비기한을 안 적은 경우)

| 경우 | 처리 |
| --- | --- |
| 관리 품목인데 소비기한·로트가 비어 있음 | 중복 검사 안 함. '필수 입력' + 노랑 먼저. 로트를 다르게 채우면 두 줄 그대로 저장 |
| 관리 품목이고 값까지 같음 / 비관리 품목이 같은 품목·단위 | 중복(빨강) + **[한 줄로 합치기]** — 첫 줄에 수량 합산, 나머지 줄 삭제 |
| 같은 품목, 단위만 다름(BOX·EA) | 중복 아님 |

- 판독 때 자동으로 합치지 않음 — AI가 같은 줄을 두 번 읽어 수량이 2배가 된 것을 놓치지 않게.
- 합친 줄 중 고치지 않은 저신뢰 수량이 있으면 합친 뒤에도 빨강 유지.
- 코드: `src/domain/plan-entry.ts` `duplicateKey`(신설)·`duplicateLines`, `PlanEditor.tsx` `mergeLines`·`severityOf`, 시험 추가(관리 품목 빈 소비기한 두 줄은 중복 아님). 단위 시험 83/83 통과.
