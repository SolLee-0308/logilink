# 대시보드 전체 재구성(시안·구현·시험 데이터) 대화 요약

## 0. 한눈에 보기

오늘은 **"모든 메뉴가 나온 뒤 한꺼번에 검토"하기로 미뤄 둔 대시보드 3종(3PL·화주사·PDA)을 재구성**했다. 순서는 검토 → 남길 항목 정리 → 화면 시안 → 구현 → 시험 데이터 → 화면 확인이었다.

웹 대시보드는 **처리할 일 → 오늘 차량 흐름(5단계) → 주의할 건 → 추이(최근 14업무일)** 4단 구조로 바꿨다. PDA는 입고검수자의 '오늘' 기준을 센터 업무일로 맞추고, 상차담당에 '출차 전' 줄을 넣었다.

| 확인 | 결과 |
| --- | --- |
| 타입 검사 | 통과 |
| 단위 시험 | 87/87 (대시보드 규칙 4개 추가) |
| 대시보드 점검(시험 DB, 읽기 전용) | 26/26 |
| 화면 촬영 (3001) | 3PL·화주사·PDA 2종 모두 정상, 화면 오류 없음 |

**모든 변경은 `feat/1114-arrival` 브랜치 작업 트리에 있고 아직 커밋하지 않았다.** 11-15 작업분(품목 다운로드·AI 판독)도 함께 미커밋 상태다. DB 구조 변경(마이그레이션)은 없다.

**다음 시작 시 할 일:** Sol이 3001에서 대시보드 4화면 확인 → 커밋 방식 결정(11-15분과 함께 / 대시보드만 분리) → 커밋 → 시연 사이트 대시보드 공개 시점 결정.

## 1. 시작 전 환경

- 시험 DB `logilink-test`를 `npx prisma dev --name logilink-test --detach`로 다시 켰다(TCP 51214). 시드는 다시 넣지 않았다.
- `npm run dev:test`는 3001 포트 충돌로 바로 끝났다. 확인해 보니 11-16 15:31에 `with-test-db.mjs`로 띄운 시험 서버가 그대로 떠 있어서 그 서버를 계속 썼다.

## 2. 남은 과제 점검

대화 기록 23의 남은 일(화면 확인·커밋·공휴일 불러오기 등)과 개발 마무리 때 정하기로 한 과제(EA 기준, 대시보드 검토, 정의서 도식 갱신, 상차 재개 사유 코드, 훼손 사진 삭제 확인)를 정리해 보고했다. 아울러 `feat/1114-arrival`에 main으로 아직 병합하지 않은 커밋이 3개 있음을 확인했다. Sol이 **대시보드 전체 검토부터** 하기로 정했다.

시안 페이지: https://claude.ai/artifact/7AxYvcqrzg9hUuCQp9fnbA (비공개, Sol만 열람)

| 시안 | 구성 |
| --- | --- |

| 처리할 일 | 승인 대기 | `/plans/approval` |
| | **품목 등록 요청**(등록대기, 메뉴 숫자와 같은 기준) | `/master/item-requests` |
| | **도착·검수 대기**(입차했고 검수 첫 입력 전 + 입고취소 뒤 재검수 전), 보조 글 '오는 중 n대' | `/plans/asn-status?tab=loaded` |
| | 검수 중(첫 입력 후 진행 중) | `/rcv-results?tab=working` |

| 주의할 건 | 기한경과 취소 대상(넓게) · 오늘 검수 차이 · 출고일 지난 상차 대기 · 오래된 미종결 — 있을 때만 카드, 0건은 '이상 없음' 한 줄 | |
| 추이 | 입고 차량(막대) + 검수 차이 비율(선) / 입고 수량(정상 입고·반송 쌓은 막대) / 검수 소요 시간(입차 → 확정 평균 분, 선) | |

### 6-2. 화주사 웹 대시보드

| 영역 | 내용 |
| --- | --- |
| 머리 줄 | 제목에 화주사명, 이용 센터가 2곳 이상일 때만 센터 고르기 |
| 할 일 | 반려된 입고예정 · 오늘 기한경과 취소 · ASN 등록할 입고예정 · 반려된 품목 등록 요청 |
| 오늘 내 차량 흐름 | 3PL과 같은 5단계(내 차량만). 화주사 ASN 조회는 상차중·상차완료를 '상차 진행' 탭 하나로 보므로 오는 중·도착·검수는 그 탭으로 이동 |
| 주의할 건 | 기한경과 승인 전 건 · 오늘 검수 차이 · 출고일 지난 상차 대기 · 오래된 미종결 |
| 추이 | 입고 수량(정상 입고·반송) / 입고예정 대비 입고율(선, 100% 기준선) |

### 6-3. 오늘 차량 흐름 (공통)

대상은 **오늘 출고일인 ASN 차량 + 오늘 상차한 무지시 차량**이다.

| 단계 | 판단 |
| --- | --- |
| 상차 대기 | ASN 등록(상차 기록 없음) |
| 상차중 | 상차 작업 중 |
| 오는 중 | 상차완료, 입차 전 |
| 도착·검수 | 입차 후 검수 확정 전 (입고취소 뒤 재검수 전 포함) |
| 입고완료 | 검수 확정 |

0대인 날에도 빈 막대 틀과 범례를 보여 준다(A안). 입차를 취소하면 입차 기록이 비워져 '오는 중'으로 돌아간다.

### 6-4. 추이 그래프 규칙

| 항목 | 규칙 |
| --- | --- |
| 기간 | 센터 업무일 기준 최근 14업무일(오늘 포함, 정기 휴무·휴무일 제외). 센터가 여럿이면 각 센터 업무일을 합쳐 최근 14일 |
| 날짜 기준 | 검수 확정 시각을 센터 업무일로 나눔 (일마감 기록이 아니라 확정 시각 — 마감하지 않은 날이 빠지지 않게) |
| 오늘 표시 | 진행 중이라 흐린 막대·점선 꼭짓점 |
| 화주사 입고율 | 그날이 입고예정일인 승인 이후 건의 수량 중 입고된 수량. **오늘 점은 그리지 않음**(화면 확인 때 하루 중간이라 약 10%로 떨어져 보여 추가로 고침) |
| 검수 소요 시간 | 입차 기록이 있는 차량만 |
| 그래프 도구 | 새 라이브러리 없이 화면 요소·SVG로 직접 그림 |

### 6-5. 화주사명 칸 (시안 댓글)

약 8글자를 넘으면 '…'로 줄이고, 마우스를 올리면 전체 이름이 보인다. 누르면 화주사명 전체와 화주사 코드가 든 작은 상자가 열린다. 표가 가로 스크롤 상자 안에 있어 상자는 화면 기준으로 띄우고, 스크롤·바깥 클릭·Esc로 닫는다. 이름을 눌러도 줄 클릭(상세 이동)은 일어나지 않는다. 3PL 대시보드의 화주사 열(기한경과·검수 차이·출고일 지남)에 적용했다.

## 7. 시험 DB 확인용 데이터

시험 DB(logilink-test)에만 넣었다. 용인1센터의 다온유통·에코프레시 차량 **76대**이고, 차량번호는 `99대1001`~`99대1076`이다.

| 구분 | 내용 |
| --- | --- |
| 최근 14업무일(11-04~11-17) | 검수 확정 69대, 그중 차이 12대(수량 부족·훼손 반송). 일부 날은 ASN을 적게 담아 부분입고 → 입고율 87~100% |
| 오늘 흐름 | 상차 대기 2 · 상차중 1 · 오는 중 2 · 도착·검수 2(입차만 1, 입력 중 1) · 입고완료 3 |
| 만든 방법 | 실제 업무 함수(입고예정 저장·승인 → ASN → 상차 → 출차 → 입차 → 검수 → 확정)로 오늘 날짜에 만든 뒤, 새로 만든 행의 날짜·시각·문서번호만 과거로 옮김. 직접 INSERT 없음, 기존 행 수정·삭제 없음, 일마감 기록은 만들지 않음 |
| 다시 실행 | `npm run check:test -- scripts/seed-dashboard-demo.ts` — '99대' 차량이 있으면 건너뛰고 안내만 |

## 10. 결론

대시보드는 **"지금 할 일 → 오늘 차량이 어디까지 왔는지 → 문제 → 지난 14업무일 추이"** 순서로 다시 짰고, 정의서 v1.9의 입차·출차와 일마감 실행 여부가 이제 화면에 보인다. 시험 DB에 확인용 데이터까지 넣어 흐름 막대와 그래프가 실제로 그려지는 것을 확인했다. 남은 것은 **Sol의 화면 확인과 커밋 방식 결정**이다.
