## 2. 화면 오른쪽 스크롤바 — 너비 흔들림 없애기

- **문제(Sol):** 내용이 길어지면 오른쪽에 회색 스크롤바가 생기면서 화면 너비가 바뀐다.
- **검토:** 스크롤바를 아예 숨기면 아래에 내용이 더 있는지 알 수 없다(Sol 지적).
- **결정:** `scrollbar-gutter: stable`로 **스크롤바 자리를 늘 비워 둔다.** 스크롤바가 생기든 없어지든 너비가 그대로이고, 내용이 길 때만 그 자리에 막대가 나타난다.
- 반영: `src/styles/globals.css`

## 3. 잔량 종결·일마감 — 전환 버튼을 다른 화면과 같게

- **문제(Sol):** 이 화면만 회색 탭이 본문 위에 있어 다른 화면과 위치가 다르다.
- **결정:** 입고예정 조회처럼 **제목 줄 오른쪽 연보라 전환 버튼(ModeSwitch)**으로 바꿨다. 정리하면 회색 탭은 '상태 거르기'에만, 업무 전환은 제목 줄 연보라 버튼으로 쓴다.
- **건수 표시(Sol):** 중요한 처리이므로 처리할 건수가 어딘가에 보여야 한다.
  - 잔량 종결 칸: 미종결 입고예정 건수 + 경과 기준 초과 건수(붉은 경고)
  - 일마감 칸: 이번 일마감 처리 대상 합계 + 기한경과 취소 대상(붉은 경고)
- **일마감 내역 카드(Sol 제안 → "마우스 올리면 내역 카드" 선택):** 일마감 칸에 마우스를 올리면 검수 실적 확정 n건 · 기한경과 취소 n건 · 미출차 출차 n대가 카드로 뜬다. 단위가 섞인 합계를 풀어 보여 주기 위해서다.
- 문구: "잔량 종결 탭으로" → "잔량 종결로 이동"
- 반영: `ModeSwitch.tsx`·`.module.css`(건수·경고·내역 카드), `ClosingScreen.tsx`, `DailyCloseTab.tsx`
- 커밋 c4aaefa → main 병합 0c0cfc5

> **작업 중 실수:** 이 PC의 `python` 명령은 윈도우 스토어 바로가기여서 아무 일도 하지 않고 끝난다. 처음에 파이썬으로 고친 내용이 실제로는 적용되지 않았는데, 적용된 것으로 잘못 보고했다. Sol이 "연보라색 탭이 안 생겼다"고 알려 주어 다시 고쳤다. 이후 파일 수정은 편집 도구나 node로 하고 git diff로 확인한다(메모리에 기록).

- Sol이 화면에서 본 "Run `next upgrade --agent=security`" 안내를 물어봤다. Next.js 보안 업데이트 알림이다.
- Sol 지시로 운영·시연 반영을 마친 뒤 **별도 브랜치(feat/1121-next-security)**에서 16.4.4 → 16.4.6으로 올렸다(eefb33d). 빌드와 타입 검사를 통과했다.
- npm audit의 나머지 경고(prisma 쪽 effect, exceljs 쪽 uuid)는 자동 수정하면 패키지가 내려가 기능이 깨질 수 있어 그대로 두었다.

### 8-1. 상차 재개 사유 코드 확정 ("코드도 맞춰줘")

- 재개 기간이 "지시 상차만, 출차 전"으로 좁아진 것(v1.6)에 맞춰 임시안을 **확정**했다.
- 기존 R01~R03·R99는 이력에 이미 남아 있으므로 번호와 이름을 그대로 두었다. 재개하면 본인 입력 정정이 다시 가능해지므로 **R04 수량 오입력 정정**을 추가했다.

| 코드 | 사유 | 쓰는 경우 |
| --- | --- | --- |
| R01 | 스캔 누락 | 실었는데 스캔하지 않은 품목이 있음 |
| R02 | 타 차량 이관 | 다른 차량에 들어가지 않은 물량을 옮겨 실음 |
| R03 | 추가 적재 | 덜 실은 예정 물량을 출차 전에 더 실음 |
| R04 | 수량 오입력 정정 (추가) | 잘못 스캔·입력한 수량을 바로잡음 |
| R99 | 기타 | 텍스트 필수 |

- 반영: 마이그레이션 `20261121000000_load_reopen_codes`(그룹 확정·설명 변경, R04 추가, 기타는 맨 아래로), `seed.ts`, `master.ts` 주석, `미확정 항목 목록.md` U57
- **시험 DB에만 적용**(조회로 확인). 운영·시연 DB는 main 병합 때 적용한다.

### 8-2. 훼손 사진 지우기 확인 창

- PDA 입고검수에서 훼손 사진을 누르면 브라우저 기본 확인 창이 떴다. 이제는 다른 확인 창과 같이 **아래에서 올라오는 확인 창**이 뜬다. 창에는 지울 사진과 품목명이 크게 보이고 [그만두기] / [사진 지우기] 버튼이 있다. 바깥을 눌러도 닫히지 않는다.
- 반영: `PdaInspectScreen.tsx`, `Pda.module.css`
- 타입 검사와 테스트 95개를 통과했다. Sol이 화면에서 확인했다.

### 8-3. 정의서 v2.2와 업무프로세스 도식 최신화

- v1.4 도식은 원본 파일이 없어 **같은 구성으로 새로 그렸다**(주체 5줄 × 단계 ①~⑦). Figma 연결이 없어 HTML(SVG) 원본을 만들고, Edge 헤드리스 모드로 PNG를 뽑았다.
  - 위쪽 전체 흐름: v1.4 이후 빠져 있던 상차 재개, 출차(사람/입차 처리/일마감 처리), 입차, 입차 취소, 첫 입력 = 검수 시작, 품목별 상차 차이 사유, 입고취소 역전표를 넣었다.
  - 아래쪽: 입고예정 상태 전이와 상태표, 차량 1대의 흐름(입고 대기 단계와 같음), 출차 구분 표, 재개·차이 사유 코드, 정합성 체크 포인트 C1~C11, 범례
  - 다음에 고칠 때는 원본 html의 좌표·글자를 고친 뒤 PNG를 다시 뽑으면 된다(방법은 파일 맨 위 주석).
- 정의서는 **v2.2 새 파일**로 만들었다. 바뀐 곳은 머리말, 도식 연결과 설명, 변경 이력 v2.2 줄, ④ 재개 사유 표, D20(재개 사유 코드), D22(훼손 사진 확인 창)이다.
