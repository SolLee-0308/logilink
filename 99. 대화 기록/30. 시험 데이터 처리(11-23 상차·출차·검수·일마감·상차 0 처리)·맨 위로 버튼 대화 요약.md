## 1. 시험 환경

- 시험 DB `npx prisma dev --name logilink-test --detach`, 개발 서버 `npm run dev:test`(3001)를 켰다. 둘 다 `03. 개발` 폴더에서 실행한다.
- 데이터 처리는 화면 버튼과 **같은 서버 함수**를 처리자 계정으로 직접 불러서 했다. 그래서 상태·이력·누계가 화면에서 처리한 것과 같다.
- 임시 스크립트 요령
  - 스크립트는 `03. 개발/node_modules/.tmp-claude/`에 두고 `npm run check:test -- <파일>`로 실행한다. 이 명령은 localhost DB가 아니면 실행되지 않는다.
  - import는 `../../src/...` 상대 경로로 쓴다. 이 폴더에서는 `@/` 경로를 풀지 못한다.
  - top-level await를 쓰려면 확장자를 `.mts`로 한다.
  - 끝나면 폴더를 지운다.

## 2. 11-23 입고예정 승인 → 상차 → 출차

- **요청(Sol):** 오늘 입고예정을 모두 승인하고 상차등록·출차까지 끝낸다. 단 1건은 출차하지 않고 상차등록까지만 한다.
- **처리:**
  - 센터 담당자가 승인했다(YI1 김하늘, IC2 정민서, INC3 김서진).
  - 화주사 담당자가 ASN을 등록하고, 화주사 상차담당 계정으로 지시 상차·상차완료·출차를 했다.
- **특이 사항:** IP-20261122-0127은 기존 ASN이 수량 일부만 담고 있었다. 남은 수량으로 ASN을 1건 더 만들어, 입고예정 라인 290개가 모두 분배되고 차이가 0이 되게 했다.
- **미출차 1건:** LO-20261122-0001(ASN-20261122-0001, LD-20261123-0001, 12가3455). 이후 이 차량은 6장에서 상차 0 처리 대상이 됐다.

## 6. LO-20261122-0001 상차 수량을 모두 0으로

- **요청(Sol):** LO-20261122-0001 지시서의 상차된 수량을 모두 0으로 만든다.
- **처리:**
  - Sol이 화면에서 이미 상차를 재개해 둔 상태였다(2차, 사유 R01).
  - 상차담당 홍민석 계정으로 상차 입력 12건을 [입력 취소]와 같은 함수로 하나씩 취소했다. 상차 입력은 **본인 입력만 취소**할 수 있다.
- **결과:**
  - 10개 품목 모두 상차 0이 됐다. 지시수량은 그대로다.
  - 상차 실적은 작업중(2차), ASN은 상차중, 지시서는 발행 상태다.
  - 원래 입력 12건은 지우지 않고 '취소됨'으로 이력에 남겼다.
- **참고:** 실은 수량이 0이면 [상차완료]가 막힌다(시스템 규칙).
- **이후(Sol 화면 작업):** 이솔 계정으로 다시 상차완료(2차)·출차를 했다. 한소율 계정이 입차하고 2건을 입력했다.

## 7. 11-23분 입고검수 — 38대

- **요청(Sol):** 오늘 검수해야 할 목록을 모두 검수 완료한다.
- **대상:** 상차완료됐는데 검수 확정이 없는 차량 38대(LD-20261123-0001~0038)
- **처리:**
  - 37대는 입차 전이어서 센터별 검수자 계정(YI1 박서연, IC2 정민서, INC3 김서진)으로 입차부터 했다.
  - 남은 수량을 정상으로 입력한 뒤 검수 확정했다.
  - LD-20261123-0001은 이미 입차돼 있었고 한소율 입력 2건이 있었다. 그 2건은 두고 남은 수량만 박서연 계정으로 채웠다.
- **결과:**
  - 검수 확정 38대(RC-20261123-0010~0047), 품목 294개, 정상 수량 합계 233,810(기본 단위)
  - 상차 수량과 다른 품목 0개(훼손·품목 불일치 없음)
  - 남은 검수 대상 0대, 검수 중 전표 0건
- **아직 일마감 전이다.** 일마감하지 않은 검수 확정 실적 38건은 다음 일마감 때 함께 마감된다.

| 항목 | 내용 |
