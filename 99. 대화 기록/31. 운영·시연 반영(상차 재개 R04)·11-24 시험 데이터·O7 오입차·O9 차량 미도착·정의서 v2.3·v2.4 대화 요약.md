## 3. O7 검수 시작 후 오입차

- 질문: 첫 입력 이후에는 입차 취소가 불가한가 → **그렇다**(K5, 첫 입력 또는 0 확인 이후 입차 취소 불가).
- 관리자 [오입차 정정] 버튼 안을 검토했다. 기존 입차 취소(VOIDED)를 재사용할 수 있지만, 실적 집계·검수 입력 수 등 몇 곳의 보완이 필요하다.
- **결론: 버튼을 넣지 않는다.** 대부분 바코드 스캔으로 입차해 오입차 자체가 드물고, 첫 스캔에서 '(품목 불일치 반송)'으로 드러난다. 실제 차량이 오면 본인 입력을 취소하고 이어서 검수할 수 있다.
- 남는 한계: 입력 취소는 본인 것만 가능, 출차 전 차량이었다면 '입차 처리(시스템)' 출차가 남아 상차 재개 불가, 차량이 끝내 오지 않으면 '검수 중'으로 남음 → 관리자 미해결 건으로 관리.

## 4. O9 상차완료 후 차량 자체 미도착

### 4-1. 현황

상차완료 후 차량이 오지 않으면 시스템에서 닫을 방법이 없다. 출차 후에는 상차 재개도 안 되고, 열린 ASN이 입고 대기를 잡고 있어 그 입고예정은 잔량 종결도 할 수 없다.

### 4-2. 검토한 안 (범위를 다시 열 때 출발점)

| 항목 | 검토 결과 |
| --- | --- |
| 누가 | 화주사 요청 + 3PL 관리자 처리(요청자·요청 경로·사유 필수). 화주사 연락 불가 예외는 두지 않음 |
| 언제 | 기다리는 시간 없이 요청 즉시. 대상은 상차완료 이후 입차 전 차량(출차 전 포함) |
| 처리 결과 | ASN '미도착 취소', 입고 대기 해제 및 새 ASN에 담을 수 있는 수량 복구, 상차 실적·출차 기록 유지 |
| 나중에 차량이 나타나면 | 새 ASN은 상차등록·출차를 다시 해야 해 비현실적 → **[미도착 처리 취소]로 원래 ASN 되살리기**(같은 상차확인서로 검수) |
| 잔량이 부족한 경우 | ① 막고 회송 / ② 경고 후 허용(검수 확정 배분이 잔량까지만 → 초과 입고, C4 예외) — **미결**, Claude는 ② 권장 |

### 4-3. 결정

- **Sol 결정: 이번 범위에서 제외한다.** 미도착 처리·처리 취소·잔량 초과 예외가 이어지는 기능 묶음이라 범위가 커진다.
- 운영 절차: 3PL 관리자·화주사 확인 후 관리자가 미해결 건으로 관리. 오지 않은 차량을 입차시켜 전 품목 0 확정으로 닫지 않는다. 늦게 오면 원래 상차확인서로 입차·검수.

v2.4 수정 내용(모두 코드와 대조해 확인):

1. 입고취소 기한을 **3PL 관리자, 해당 실적의 일마감 전까지**로 통일(적치 시작 전 조건은 적치 모듈 도입 후).
2. 4-2 입고검수: 배분된 입고예정 중 종결·취소된 건이 있으면 입고취소 불가.
3. O9 표: 잔량 종결은 미도착 차량의 열린 ASN에 담긴 입고예정만 막힘, 일마감 시스템 출차 대상 조건 명시, 다른 차량 입차·검수는 가능하나 새 ASN에 담을 수 있는 수량은 줄어듦.
4. '잔량 복귀' → '입고 대기 해제, 새 ASN에 담을 수 있는 수량 복구'.
5. 핵심 원칙 4·1장·③·D7: "지시 상차는 ASN을 거치며, 예정 외 차량은 ASN 없이 무지시 상차로 처리할 수 있다"로 통일.
6. Q2·D32·전량 미도착 표: 'ASN 검수 대상 품목' → '그 차량의 검수 대상 품목'.
7. 5-3: 실제 확정한 입고·반송 수량만 누계 반영, 모든 열린 ASN의 입고 대기가 없을 때 잔량 종결 가능. 5장 순서 5-1 → 5-2 → 5-3.
