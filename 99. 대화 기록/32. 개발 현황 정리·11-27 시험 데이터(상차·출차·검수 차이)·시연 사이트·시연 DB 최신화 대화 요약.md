## 3. 11-27 상차·출차·입고검수 처리 (시험 DB)

### 3-1. 처리 방법

- 실제 서비스 함수를 그대로 썼다: `createAsn` → `startOrderedLoad`·`addLoadInput`·`completeLoad`·`departLoad` → `startRcv`·`addRcvInput`·`confirmRcv`. 처리 규칙은 화면에서 처리할 때와 같다.
- 입고예정 1건을 차량 1대로 처리했다. ASN 수량은 입고예정 수량 그대로 넣었다.
- 처리자는 화주사별 담당자(ASN)와 상차담당(상차·출차), 센터별 검수자다. 이천2센터는 정민서, 인천3센터는 김서진, 용인1센터는 최우진이 맡았다.
- 상차와 검수 수량은 품목코드로 입력했고 기준 단위로 셌다.
- 다시 실행되는 것을 막는 장치를 넣었다(이미 ASN이 있는 건이 있으면 중단). 스크립트는 한 번만 실행했다.
- 훼손 반송은 사진이 있어야 확정되므로 넣지 않았다.

## 5. 시연 DB 최신화 (시험 DB 전체로 교체)

### 5-1. 결정

시연 DB에는 11-20까지의 데이터만 있었다. 11-27 입고예정 38건(11-22·11-24 등록분)은 없었다. 또 11-27 검수 초과분 2건이 시연 DB에 없는 입고예정으로 배분되어 있었다. 그래서 오늘 데이터만 떼어 옮기면 수치가 맞지 않는다. 두 안 중 **Sol이 "시험 DB 전체로 교체"를 골랐다**(11-20 교체와 같은 방식).

### 5-2. 처리

| 단계 | 내용 |
| --- | --- |
| 백업 | 시연 DB 전체 3,917행 → `C:\Users\solle\work\logiLink-backup\시연DB_백업_2026-11-27_교체전.json` |
| 교체 | 한 트랜잭션 안에서 `session_replication_role = replica` → tb_* 38개 표 DELETE → 시험 DB 행 복사(`row_to_json` → `json_populate_recordset`) → id 시퀀스 맞춤 → commit. 실패하면 rollback |
| 제외 | `tb_session`(로그인 세션 유지, 다시 로그인하지 않아도 됨) |
| 대조 | 표 38개 건수 불일치 0, 11-27 입고예정 38건(입고완료 18·부분입고 18·반려 2) 확인 |

### 5-3. 바뀐 점

- 시연 DB는 이제 시험 DB와 같다. 11-21~27 처리분과 11-28~12-03 입고예정(승인대기 포함)이 함께 들어갔다.
- 시연의 예전 로그인 기록(45건)은 시험 DB 기록으로 바뀌었다. 원본은 백업 파일에 있다.
- 계정은 시험 DB 계정이다. 선생님 화주사 계정은 hf.lee.sol이고, 비밀번호는 마스터다.
- 로그인한 뒤의 화면은 점검하지 않았으므로 Sol이 확인해야 한다.
